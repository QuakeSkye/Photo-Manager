# L01–L05 图库隔离、确认和恢复修复

日期：2026-11-05。代码版本仍为 1.0.3；数据库新增 migration 0012。

## 已确认的产品行为

- 用户确认隔离异常项后，可以继续其余可安全处理的文件。
- 取消保留已导入照片和临时文件；不自动清理。结果不明的路径保留独立保护，不继续占用全局任务租约。
- 导入运行中关闭窗口，选择继续导入或停止并退出。退出等待工作线程收尾，下次启动由用户确认恢复。
- 原来源身份不足以恢复旧授权时，结束旧任务并重新预检、重新确认；不会按盘符或同名目录冒认原卡。

## 实现范围

### L01

回收候选限定当前 Library 和当前 RootBinding。确认包含具体标记、照片/资产版本、绑定和路径的集合摘要；执行在事务内核对摘要，重试及每次 Shell 动作前核对当前图库。其他图库的任务状态不混入当前页面。

导入也核对任务冻结的图库和目标绑定，切换当前图库不能把旧任务重定向到新目录。

### L02

导入轮询同步更新展示与提交使用的草案，拒绝过时响应，避免重叠轮询。草案摘要变化会关闭旧确认框。后端对照持久化 Proposed generation 的摘要，重试不能代替用户确认；拒绝旧摘要。

### L03

增加任务内来源重新选择入口。强身份来源核验后允许显式恢复；有限身份来源撤销旧任务授权并返回重新预检流程。重新选择来源清除旧预检草案。

来源完全不匹配时拒绝直接恢复，用户仍可取消旧任务后选择来源重新导入。

### L04

新增 creation_started 边界：只有已持久化即将创建文件的记录才可能被判断为创建结果不明。新任务中未到此边界的排队项可以恢复；旧数据库记录没有这项证据，迁移默认保守处理。

异常项隔离以不可变 source item 记录保存，跨计划更新仍有效。后续预检、验证和执行排除这些项目；保留文件和原计划目标路径在界面可见。其余项目完成后仍报告有未处理项，用户可以取消剩余任务结束它。

不完整临时文件不再自动删除；已完成的发布事实和索引恢复继续保留。

### L05

运行中请求取消，后台在安全边界收尾；校验中也接收取消信号。等待来源、等待空间、计划确认和需处理状态均有取消入口。无工作线程时以数据库事务关闭授权、记录未决步骤并释放 claims/reservations/lease。

取消不依赖目标盘在线。未知临时文件及可能发布的目标保留持久化路径保护；新任务不能在这些路径上建立写入预约。

关闭窗口通过原生确认框发出停止请求，阻止新导入工作线程，等待当前线程退出后关闭应用。

## 验证

- 前端：71 条测试通过（最终使用 `npm test -- --maxWorkers=1` 复验），包括异步更新计划后提交新摘要、等待空间取消、明确确认异常隔离。两轮普通运行曾全部通过；与 Rust 全量并行的最终普通运行中，原有 D 键标记用例出现一次等待按钮失败（70 通过、1 失败）。没有修改该用例或将这次波动隐去。
- Rust：新增跨图库旧确认拒绝、旧计划拒绝及重试不代替确认、两文件排队中断恢复、隔离首项继续第二项、重启后原来源重选、有限身份重新预检、退出暂停可恢复、导入目标不能重定向、目标离线取消等回归。
- Rust 全量：164 通过，2 项原有外部环境测试忽略。
- ESLint/TypeScript、前端构建、Clippy、安全审计及 3 条现有 E2E 边界断言通过。
- 数据库历史版本向前迁移及旧任务证据保留由现有迁移测试和新增恢复测试覆盖。

测试只使用生成的可丢弃夹具，未对用户图库导入或回收。所谓现有 E2E 是源码/配置边界断言，不等同于桌面实机验收。有限身份分支用数据库夹具模拟，未使用真实 exFAT 内存卡；原生关闭确认框未进行人工点击验收。未构建或安装新的安装包。

## 保留的限制

- 不自动清理临时文件，也没有在本轮新增解除不确定路径保护的人工处理工具。
- 工作线程遇到数据库不可写等故障时，不能伪造取消成功；仍保留证据并报告需处理/重启。
- 停止请求不会强制中断正在进行的系统调用；退出等待安全收尾，不承诺固定退出时长。
- 本轮没有实施查重减少读盘、预览缓存、历史配对和日备份修复。

原有未提交修改保留；本轮未提交或推送 Git。
