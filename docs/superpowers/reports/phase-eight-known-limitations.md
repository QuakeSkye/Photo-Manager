# 阶段 8 已知限制（v1.0.1）

日期：2026-08-09

- 1.258 TB 是 200,000 个 NTFS 稀疏 Asset 的逻辑容量；最终 Run 实际分配 86.609 GiB，机械盘吞吐另以真实分配的 2 GiB 顺序样本和 64 MiB 非缓冲随机读取样本测量。
- `IFileOperation` 的最终身份复核与 Windows Shell 实际回收动作之间仍有无法完全消除的非原子窗口。v1.0.1 以单 asset STA 调用、逐文件回调、动作后 Fact 提交和故障闭锁缩小并暴露该窗口。
- Windows 回收站不是照片备份，仍会受容量、组策略、清空和系统维护影响。
- SQLite 一致备份只保护目录、任务和安全证据，不备份 JPG/RAF 原片。
- fault latch 在同一进程内不会自动恢复；数据库耐久性、Root 身份、协调器或能力边界故障后，必须安全退出并重启，再重新通过全部启动检查。
- DPI 验收使用实际安装候选的 WebView2 CDP device-scale/viewport 矩阵，不能代表每一种显卡、多屏排列、HDR 或第三方辅助技术组合。
- 安装包和 EXE 没有组织代码签名证书，Authenticode 为 `NotSigned`。SHA-256 绑定仍有效，但若今后签名或重建，当前全部候选证据自动失效并必须重跑。
- 前端测试曾在并行 runner 负载下出现一次 1 秒等待超时；冻结门固定单 worker 后 39/39 通过。该项登记为已缓解、无数据安全影响的 Low 缺陷。
- 所有 Import、Recycle、缓存、损坏、空间不足、安装和恢复测试只使用生成或明确可丢弃数据；没有对用户唯一照片执行导入、回收或删除。
- 软件健康时 Import/Recycle 默认可用，不再依赖用户确认文件；这不替代照片备份、首次可丢弃演练或界面中的具体动作确认。
