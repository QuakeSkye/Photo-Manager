# 首次真实照片 Import / Recycle 前操作清单

v1.0.1 在运行环境健康时默认开放 Import 和 Recycle，不需要软件内人工解锁。本清单是首次正式使用前的独立安全准备，不是权限开关，也不能绕过自动故障 gate。

## 共同准备

- [ ] 已安装版本显示 1.0.1，EXE SHA-256 为 `bc855771910129719c4c56d513c024debd832c23fffe71da909ea2c7079801d8`。
- [ ] 唯一照片至少有一份位于另一设备或存储服务、可恢复且已抽样验证的独立备份。
- [ ] 已阅读最终报告和已知限制，并理解 Windows 回收站与 SQLite 备份都不是照片备份。
- [ ] 设置页“写入安全状态”显示 Import 与 Recycle 均为开放；若关闭，先安全退出并处理显示的原因，不尝试绕过。
- [ ] 先用另一组可丢弃 JPG/RAF 完成一次 Import、标记、Recycle 和回收站恢复演练。

## Import 前

- [ ] 来源卡/来源卷与 Fuji 图库是不同卷，来源路径、目标图库和日期目录均正确。
- [ ] 来源卷未被设置为 AppData、Fuji 图库或缓存写位置；应用报告的来源写请求为 0。
- [ ] 已检查完整 Import 计划、JPG/RAF 名称族、重复/冲突、预计新增字节和目标卷余量。
- [ ] 第一批真实导入控制在易于人工核对的数量；完成后抽查源文件仍在、目标 hash/大小正确且没有覆盖既有照片。

## Recycle 前

- [ ] 已逐项检查待删除照片的缩略图、格式、相对目录、物理文件数和总容量。
- [ ] 已理解配对 JPG/RAF 可能作为同一 Photo 的多个物理文件逐个进入回收站。
- [ ] Windows 回收站对目标卷可用、未被策略禁用，并有足够容量；没有启用“删除时不移入回收站”。
- [ ] 已确认独立照片备份可恢复，并已在可丢弃文件上演练从 Windows 回收站恢复和应用重扫。
- [ ] 若任务出现“NeedsAttention”或结果不明，停止后续 Recycle，保留现场并先查看报告；不要手工清空回收站。
