# 本地 Fuji 照片管理器 v1：导入、设置、恢复与报告 UI 设计

- 状态：书面规格已由用户确认
- 日期：2026-07-29
- 上位产品规格：`2026-07-28-local-photo-manager-design.md`
- 核心视觉规格：`2026-07-28-local-photo-manager-ui-design.md`
- 导入第 1 步：`2026-07-29-local-photo-manager-import-location-ui-design.md`
- 覆盖范围：导入预检、确认、执行、恢复与报告；设置；首次绑定；操作记录与扫描/删除报告

## 1. 设计结论

v1 始终只有两个照片视图：**图库**和条件显示的**待删除**。导入、设置、恢复、操作记录和报告是临时工作流或工具页，不是照片视图，不增加常驻顶栏页签。

所有工具页复用已确认的白色沉浸式视觉语言：白色工作区、浅灰背景、细边框、克制阴影和深色主按钮。导入、恢复与报告页继续使用“左侧步骤 + 中央内容 + 右侧摘要与动作”的同壳布局；右栏上方只放本步摘要，页面级主动作固定在右栏最下方，与上方内容之间保留弹性留白。设置页沿用已确认的 A 方案，单项“重新选择/更改”按钮与对应设置同行，确认动作位于模态框底部。

界面只展示用户能理解并能核对的信息，例如卷名、文件夹路径、文件名、数量、容量、日期、结果和可执行动作。`RootId`、`LibraryId`、`PhotoId`、`AssetId`、Job/Attempt/Step ID、卷 GUID、文件 ID、内容哈希、nonce、capability 和数据库状态码都不得出现在普通界面、确认框或报告中。

## 2. 共享外壳与导航

### 2.1 顶栏

- 左侧保留简洁品牌标识和“图库”。
- 只有存在待处理删除项时显示“待删除 N”；数量归零后整项消失。
- 工具页中央显示当前上下文，例如“导入照片”“设置”或“操作记录”。
- 右侧提供独立的非页签“设置”工具按钮和“返回图库”；导入流程中返回前必须按当前状态处理离开规则。
- 不增加“报告”“导入”“设置”形式的常驻照片视图页签。

“设置”按钮可通过 `Enter` 或 `Space` 打开。进入设置时记录来源路由、排序和当前 Photo；返回时优先恢复来源并把焦点交还“设置”按钮。来源待删除路由已经失效或 Photo 已不存在时，按核心 UI 路由保护回到图库。直接打开设置路由时，“返回图库”进入图库当前游标；首次未绑定 Root 时照片文件夹页是启动门，不允许绕过后进入虚假空图库。

### 2.2 工具页布局

```text
┌──────────────────────────────────────────────────────────────────┐
│ FUJI 图库  图库 [待删除 N] │ 当前工具页       设置   返回图库 │
├────────────┬──────────────────────────────────────┬──────────────┤
│ 步骤/分组  │                                      │ 本页摘要     │
│            │              主内容                  │              │
│ 当前项     │                                      │ 弹性留白     │
│            │                                      │              │
│            │                                      │ 底部动作     │
├────────────┴──────────────────────────────────────┴──────────────┤
│ 当前状态                     简短安全说明              状态文字 │
└──────────────────────────────────────────────────────────────────┘
```

- 导入页左栏固定显示四步：选择位置、预检与确认、正在导入、导入报告。
- 设置页左栏显示照片文件夹、预览缓存、Photoshop、操作记录。
- 报告详情可使用“摘要 + 明细”的主内容，不显示照片 Filmstrip。
- 页面级错误就地持续显示；只用 toast 表达非关键、已经完成的反馈。

### 2.3 活动任务与跨工作流导航

存在未终结的 Root 扫描、Import、Recycle 或恢复协调时，共享外壳持续显示活动任务状态条。状态条使用用户文案、开始时间、已完成/总数和当前阶段，并提供“返回进行中任务”；不得显示 Job、Attempt、Step、RootId、卷 GUID、文件 ID 或哈希。前端必须消费 Rust 权威任务摘要，不能因用户切换页面就把任务视为结束。

- Import 执行活动时可以进入图库或待删除页只读浏览、复核和取消标记，但待删除页的“执行删除…”和删除重试全部禁用，并提供返回 Import 进度页的入口。
- Recycle 执行活动时可以只读浏览，`D/R` 保持暂停；导入页允许查看位置或完成只读预检，但“确认并导入…”、重试导入和其他会启动 ImportAttempt 的动作禁用，并提供返回 Recycle 状态页的入口。
- Root 扫描活动时允许按第 4.3 节规定返回扫描进度，图库、来源和缓存位置变更继续禁用；未终结恢复协调时采用相同限制。
- 离开正在进行的只读预检前必须确认“取消预检并离开”；选择不离开时保持扫描和当前路由，确认后先提交取消、停止扫描，再导航，且不生成可执行计划。
- 离开正在导入或 Recycle 执行页只改变可见路由，不隐式发送取消。用户只能通过页面内“取消剩余…”及其确认框停止后续工作；关闭应用也不得伪装成已取消，重启后按恢复状态处理。
- 活动任务到达终态后状态条消失，完成或问题报告入口按第 5 节呈现。

## 3. 导入流程

### 3.1 第 1 步：选择位置

页面布局和目录规则以 `2026-07-29-local-photo-manager-import-location-ui-design.md` 为准。再次插入同一张卡时只识别并预填来源，不自动扫描。用户必须点击右栏底部“开始只读预检”。

### 3.2 启动只读预检

点击后进入第 2 步的扫描状态：

- 标题显示“正在只读预检”，并持续显示所选来源文件夹和目标图库的用户可读路径。
- 中央显示已扫描文件数、当前目录和活动指示；不虚构剩余时间。
- 说明“不会复制、移动或删除内存卡中的文件”。
- 右栏底部只提供“取消预检”；取消停止继续扫描并返回选择位置，不生成可执行导入计划。
- 预检期间不创建目标日期目录、不复制文件，也不自动进入导入执行。

来源拔出、身份变化或读取失败时停止预检，就地显示具体原因和“重新选择来源”或“重新开始预检”，不沿用不完整结果。

### 3.3 第 2 步：预检与确认

预检完成后，中央先显示整批摘要：

| 分类 | 展示内容 |
|---|---|
| 将新增 | 逻辑照片组、真实文件数、预计新增容量 |
| 已存在，跳过 | 经本次预检证明内容相同的文件数 |
| 同名但内容不同 | 将使用统一安全后缀的照片组数及示例 |
| 日期未知 | 将进入 `Unknown-Date` 的文件数 |
| 无法读取 | 文件数、文件名和可读原因 |

- v1 默认处理全部可安全导入的受支持文件，不提供逐文件勾选或自动推荐删除。
- JPG/RAF 配对组按一个逻辑组呈现，并允许展开查看两个真实文件及各自计划位置。
- 失败项不会被混入“跳过”；少量失败不阻止其余安全项目，但必须在确认按钮上方持续突出。
- “已存在”是预检时结论；执行时还会重新验证。若变化意味着应新增复制或采用另一目标计划，当前执行不会静默转换，而是停止受影响项、返回确认新的计划代次；无法安全证明时显示冲突或需要处理。界面用一句话说明这一点。
- 明细默认显示相对 Fuji 图库的计划位置；来源和目标根目录可在页首查看。内部身份和哈希不显示。

首次只读预检完成时展示的是尚未创建 ImportJob 的“计划草案”，普通 UI 只称“本次导入计划”，不显示草案或 generation 的内部 ID。只有用户在最终确认框点击“开始导入”时，Rust 才创建 ImportJob 和首个 Confirmed generation；此后执行前刷新若改变未解决项的“跳过/新增/冲突”分类、组后缀或目标名称、最终目标路径、单文件计划字节，才在该 Job 下追加新的计划代次。已经成功发布/索引或已有可重新验证 partial 造成的本轮剩余容量下降不是计划变更，只形成新的执行前验证和空间检查。页面用“此计划已更新，请重新确认”以及新旧数量/容量/目标名称差异表达变化。

右栏上部显示将新增的照片组、真实文件数、预计容量和失败数；底部固定显示：

1. “返回选择位置”；
2. 深色主按钮“确认并导入…”；没有任何可导入文件时禁用并解释原因。

### 3.4 最终导入确认与空间错误

“确认并导入…”先打开模态确认，不创建 ImportJob、目录或照片文件。确认框显示当前计划草案（已有 Job 的重试场景则为当前待确认代次）的：

- 将新增的逻辑照片组、真实文件数和预计容量；
- 将跳过、改后缀、日期未知和无法读取的数量；
- Fuji 图库目标路径；
- “内存卡保持只读；已安全发布的文件即使之后取消也会保留”。

主按钮为“开始导入”，次按钮为“取消”。对话框打开时禁用全局照片浏览与删除快捷键。

用户点击最终“开始导入”时，Rust 先以事务创建 ImportJob 和首个 Confirmed generation（已有 Job 时确认当前 Proposed generation），但仍不创建 Attempt、OperationReservation、目录或照片文件；随后只读刷新来源、目标、跳过证明和安全名称。若未解决项的“已存在/将新增/冲突”分类、最终后缀或目标名称、最终目标路径、单文件计划字节发生变化，当前确认立即失效，页面返回第 2 步并突出显示差异；用户必须确认新的最终计划代次，应用不得沿用旧确认静默执行。

执行或恢复时重新验证旧的“已存在，跳过”项，必须再次用稳定句柄完成双端完整哈希、逐字节比较以及比较前后身份与计划路径绑定证明。若内容变化使上述任一计划字段发生变化，就不得在当前执行中把该项从“跳过”直接改成“新增”；当前执行停止受影响项，生成新的计划代次并返回第 2 步由用户重新确认。若无法完成完整证明但尚不能确定计划字段变化，则显示“需要处理”并停止，不猜测为新增或跳过。

只有最新计划代次已由用户确认且紧邻执行的只读刷新仍一致后，才在真正开始首个复制步骤前统一检查一次磁盘空间。空间检查使用该最终代次的全部预计新增容量；检查通过前不创建 ImportAttempt、OperationReservation、日期目录或 partial。如果不足：

- 不创建任何新目录或 partial；
- 页面标题显示“空间不足，尚未开始导入”；
- 显示预计新增容量、当前可用容量和仍缺少的容量；
- 提供“重新检查空间”“返回选择位置”和“取消导入”；
- 不自动循环检查，不把空间不足显示成等待中或成功。

“重新检查空间”是用户显式发起的再次检查，不构成后台轮询；若再次检查前计划内容已变化，必须先返回第 2 步确认新代次，不能直接使用新的容量继续执行。

执行中如果底层实际返回空间不足，则立即停止后续复制，进入部分完成的错误摘要；已发布文件不回滚。用户释放空间后只能通过“重试未完成项”创建新的重试，不能继续改写原结果。

### 3.5 第 3 步：正在导入

中央区域显示：

- 整体完成进度：已完成真实文件数 / 计划真实文件数；
- 当前文件名、当前动作的用户文案，例如“正在复制”“正在验证”“正在保存”；
- 已新增、已跳过、失败和未开始数量；
- 一条持续可见的“内存卡只读”状态。

不显示哈希值、partial 文件名、内部步骤或数据库提交术语。进度可以按真实完成结果前进，不在文件验证和安全发布完成前提前计为新增成功。

右栏底部提供“取消剩余导入…”。取消需要确认，并明确：

- 只停止尚未发布部分；
- 已发布照片会保留在图库；
- 完成后将生成部分完成报告。

取消请求提交后按钮显示“正在停止”，禁止重复点击。页面可以渐进报告已经完成的照片，但不得强制切换图库当前照片。

### 3.6 等待原始内存卡

导入执行中拔卡或重启后找不到原卡时显示持久页面状态“等待原始内存卡”：

- 显示用户选择过的卷名和相对来源文件夹，不显示卷 GUID 或内部 ID；
- 显示已完成、未完成和已发布文件数；
- 说明“请插回开始本次导入的内存卡”；
- 插回后先只读验证，不因盘符相同自动继续；
- 验证为原卡后显示“确认后继续”，用户点击并再次确认才创建新的重试 Attempt；
- 另一张卡、来源文件变化或无法证明时保持停止，并给出重新选择或取消剩余导入的可用动作。

取消剩余导入不删除已发布文件，也不把不明 partial 描述为已清理。

### 3.7 启动恢复

应用启动发现未终结导入、删除或协调工作时，不静默恢复任何写操作。先显示只读“恢复上次操作”摘要：

- 操作类型、开始时间和用户可读来源/目标；
- 已完成、未完成、失败和需要处理的数量；
- 已经发生且不会回滚的事实，例如“已有 34 个文件保存到图库”；
- 当前物理事实与只读协调结论；
- 与操作类型和证据状态严格匹配的动作。

动作矩阵如下：

表中的反引号状态名只用于规格映射；页面使用“可重试的删除”“删除结果需要确认”等中文文案，不显示内部状态码。

| 恢复类型 | 初始动作 | 允许继续的条件 | 取消含义 |
|---|---|---|---|
| 未终结 Import | “继续导入…”、“取消剩余导入”、“查看详情” | Root、原卡、源文件和目标计划重新验证通过；缺卡时先进入“等待原始内存卡”并由用户确认原卡 | 只停止未发布步骤；已发布文件和不明 partial 按事实保留 |
| `RetryableFailed` / `Partial` 删除 | “重试剩余文件…”、“取消剩余删除”、“查看详情” | 仍在原位的剩余文件与冻结身份匹配，并重新确认 Photo 数、文件数和容量 | 只取消尚未成功的剩余意图；不改写已回收或失败事实 |
| 删除结果不明 / `NeedsAttention` | “重新扫描确认”、“查看详情”，存在尚未执行意图时另有“取消剩余删除” | 重扫证明原身份文件仍在原位后，才出现“重试剩余文件…” | 只取消尚未执行意图；未知结果继续保留并提示检查 Windows 回收站 |

无法安全证明的结果进入“需要处理”，不得提供泛化的“继续”或“标记为成功”。所有恢复 Attempt 与 Resolution 只追加新事实，不改写旧结果。

### 3.8 第 4 步：导入报告

导入达到终态后直接进入本次报告。页首结果必须区分“完成”“部分完成”“已取消”“需要处理”，不能用一个绿色成功页覆盖失败。

报告显示：

- 新增文件数与实际容量；
- 已存在并跳过的文件数及当前已有位置；
- 使用安全后缀的照片组及最终名称；
- 日期未知、文件时间未保留等警告；
- 失败、取消、未开始和需要处理的文件及可读原因；
- 每次重试的时间和结果，以“第 1 次”“第 2 次”呈现，不显示 Attempt ID。

每行可展开查看文件名、来源相对路径、目标相对路径和结果。报告不允许编辑旧结果为成功。

右栏底部提供“返回图库”和“再次导入”；存在可安全重试项时额外显示“重试失败项…”，确认后只处理尚未发布且重新验证通过的文件。

## 4. 设置页

### 4.1 信息架构

设置采用已确认的 A 方案：左侧为四个清晰分组，中央是当前分组的连续主面板，右侧显示简短状态摘要。每项设置在验证和确认后单独生效，不提供容易误解的整页“保存全部”。

左侧分组为：

1. 照片文件夹；
2. 预览缓存；
3. Photoshop；
4. 操作记录。

### 4.2 照片文件夹

- 显示当前完整路径和“已连接”“离线”或“需要重新选择”等文字状态。
- “重新选择”打开 Rust 原生文件夹选择器；候选验证失败时显示具体用户原因，原绑定不变。
- 能证明为原图库时，确认框写“重新连接原图库”，并说明会保留浏览位置、待删除标记、索引和历史。
- 不能证明为原图库时，确认框写“切换到新的 Fuji 图库”，并说明旧状态保留但不会迁移，新图库需要重新扫描。
- 有未完成 Root 扫描、导入、删除、恢复协调或缓存切换时禁用重新选择并说明原因；全量扫描必须先确认取消，不能用重新选择绕过扫描门。

首次启动尚未绑定图库时，使用同一页面结构显示“选择照片文件夹”。验证并确认前不显示虚假的空图库；取消则停留在绑定页。普通界面不展示任何 Root 或 Library 内部编号。

### 4.3 Root 扫描与扫描报告

Root 绑定确认后的扫描按身份结果分为两种：

- **首次绑定或新图库切换**：启动全量扫描。扫描完成前保持在扫描门，不显示虚假的空图库；只有扫描完成且权威结果已提交后，才能显示“进入图库”。若从导入选择位置页发起，完成后的主动作是“返回选择位置”，同时提供“进入图库”。
- **原 Root 可靠重连**：复用既有索引并启动增量扫描。用户可以立即返回发起上下文或图库；从导入页发起时返回“选择位置”并重新验证预检条件。共享状态条显示“正在更新图库”以及“查看进度”。取消或失败不删除旧索引，也不把未重新观察的条目伪装成已经确认。

扫描进度页显示扫描类型、用户可读 Root 路径、已检查目录/文件数、已发现逻辑照片数、忽略和警告数量及当前相对目录；不显示内部 ID，也不虚构剩余时间。扫描照片文件始终只读，Catalog 的 SQLite 提交不改变照片文件。

单个不支持格式、无法读取文件或被跳过的 reparse 路径记入警告并继续，不把整次扫描伪装成失败；Root 身份丢失、数据库无法耐久提交或其他使剩余范围无法可靠枚举的错误才进入扫描失败。全量扫描可靠完成但确实发现 0 张照片时，用户点击“进入图库”后才显示真实的图库空状态。

动作与状态：

| 状态 | 动作与结果 |
|---|---|
| 正在全量扫描 | “取消扫描…”；确认取消后停止继续枚举，已观察索引保留但标记为扫描未完成，不允许用它显示普通空图库 |
| 全量扫描已取消 | “继续扫描”“重新选择照片文件夹”；仍停留在扫描门 |
| 全量扫描失败 | 显示受影响相对路径和可读原因；提供“重试扫描”“重新选择照片文件夹”，不显示整体成功 |
| 全量扫描完成 | 显示发现、忽略、无法读取和警告摘要；根据发起上下文显示“进入图库”或“返回选择位置” |
| 正在增量扫描 | 可“返回发起页/图库”“查看进度”或“取消扫描…”；离开进度页不取消后台扫描 |
| 增量扫描取消或失败 | 保留既有索引，在图库显示持续警告和“继续扫描/查看报告”；不得把旧观察时间描述为最新扫描完成 |
| 增量扫描完成 | 状态条消失，生成不可变扫描报告；非关键完成反馈不抢占当前 Photo |

取消扫描不会回滚已经安全提交的 Catalog 观察，也不会改变 Root 绑定。切换到另一个 Root 必须重新经过第 4.2 节确认，不能把“取消扫描”当作撤销绑定。

每次扫描在完成、取消或失败时都生成不可变扫描报告并进入“操作记录”；报告明确标明扫描是否完整。应用重启发现首次/新图库全量扫描未完成时仍停留在扫描门，提供“继续扫描”或“重新选择照片文件夹”，不得把部分索引显示成完整图库；未完成的增量扫描可以按正常启动扫描重新调度，但必须显示活动状态和取消入口。

### 4.4 预览缓存

中央显示：

- 当前缓存父目录的用户可读路径；
- 实际占用、当前容量上限和所在卷可用空间；
- 可调整的容量上限控件，默认 `32 GB`，任何可提交值都必须大于 0 且不得超过绝对上限 `64 GB`；
- “按需增长，不会预先占满”和“由应用自动淘汰”的说明。

不得提供“手动清理缓存”按钮。界面明确缓存不是照片备份，淘汰缓存不会删除照片。

更改缓存位置时：

1. 用户选择的是父目录，专属子目录名称不作为普通 UI 信息展示；
2. 先验证新位置不在图库、内存卡、应用数据目录或 reparse 路径内，且不存在反向包含；
3. 显示确认，说明新预览按需生成、旧缓存不搬迁且会在可安全证明归属时后台渐进淘汰；
4. 只有用户确认且新位置创建成功后才切换；取消或失败完全保留原设置。

点击任一容量选项不能立即生效，必须显示确认：旧上限、新上限和影响。缩小容量时说明会后台渐进淘汰较旧预览，不要求页面等待；增大容量时说明只是上限，不会立即占用。取消保持原上限和选中状态。

缓存位置离线时照片仍可浏览；界面显示“缓存暂时不可用，将按需重新生成”，不把缓存异常描述为照片丢失。

### 4.5 Photoshop

- 未配置时显示“尚未选择 Photoshop”和“选择 Photoshop”。
- 设置页“选择/重新选择”以及图库首次点击按钮都由 Rust 打开原生文件选择器。
- 验证成功后显示“Adobe Photoshop”“Photoshop.exe · 已验证”等用户信息；不显示 `ToolId`。
- 选择无效程序或取消时不覆盖当前有效配置。
- 已配置程序后来缺失或验证失败时显示“需要重新选择”；图库仍可浏览和打开文件位置，但“用 Photoshop 打开 RAF”暂时不可用。
- 说明文件交给 Photoshop 后，其修改、保存和附属文件由 Photoshop 管理，本应用不替代其保存行为。

### 4.6 设置变更共同规则

- 每次位置或容量变更都先验证、再显示影响摘要、最后由用户确认；不能单击即切换。
- 未终结 Root 扫描、Import、Recycle、恢复协调或缓存切换期间，图库、来源和缓存位置变更保持禁用并显示活动任务与返回入口；Rust 同时拒绝绕过请求。
- 进行中状态禁止重复提交和离开确认框的快捷键操作。
- 成功后显示“当前设置已保存”；失败就地显示原因和“原设置未更改”。
- 路径选择和状态错误只使用用户可理解的文字，内部 ID 只允许进入开发诊断日志。

## 5. 操作记录与报告

### 5.1 入口

- 顶栏不增加常驻“报告”页签。
- 导入完成后直接进入本次导入报告。
- 删除全部成功后返回图库，通过一次不打断浏览的“查看报告”消息进入本次报告；仍有问题时留在待删除页显示本次结果和处理动作。
- 历史扫描、导入和删除记录统一从设置页“操作记录”进入。

### 5.2 操作记录列表

列表按时间从新到旧显示：操作类型、开始时间、完成状态、简短数量摘要和是否仍需处理。允许按“全部 / 扫描 / 导入 / 删除”筛选，不提供编辑、清空或伪造完成的动作。

状态使用用户文案：完成、部分完成、已取消、失败、需要处理、等待原始内存卡。列表不显示内部操作编号。

### 5.3 报告详情

- 扫描报告：已发现照片、忽略格式、无法读取、跳过 reparse 路径和其他警告。
- 导入报告：按第 3.8 节展示新增、跳过、改后缀、日期未知、失败、取消、警告和重试。
- 删除报告：逻辑照片数、真实文件数、容量，以及每个 JPG/RAF 的“已移入回收站”“仍在原位置”“结果不明”“已取消剩余删除”。

报告中的物理事实不可编辑。后续重试、取消剩余意图、重新扫描或确认恢复只追加新的时间线事件；旧的成功、失败和不确定结果始终保留。

删除报告若有 `RetryableFailed` 或部分完成，允许在重新确认剩余文件数与容量后“重试剩余文件”，或“取消剩余删除”。结果不明时先“重新扫描确认”；无法证明时继续提示检查 Windows 回收站，并在存在尚未执行意图时保留“取消剩余删除”。该动作只取消后续意图，不改写未知或已回收事实；始终不提供“标记为成功”。

## 6. 错误与可访问性

- 错误必须紧邻受影响路径、文件或动作，写明用户能采取的下一步，不只显示“操作失败”。
- 批次级安全错误使用持续可见的页面消息，不在几秒后消失。
- 所有状态同时使用文字、图标和必要的数量，不能只靠红/绿颜色。
- 长路径允许换行和复制查看，但展示路径不能作为写操作授权。
- 右栏底部动作始终可见；高度不足时先压缩弹性留白，再只滚动中央内容或右栏上部摘要。
- 1100 × 700 最小窗口及 Windows 125%/150% 缩放下，确认数量、路径尾部、错误原因和主按钮不得被截断。
- 模态框关闭后焦点返回发起按钮；确认期间禁用全局 `D/R/←/→` 和滚轮照片导航。

## 7. UI 验收条件

1. 全应用仍只有“图库”和条件显示的“待删除”两个照片视图；导入、设置和报告不成为第三个页签。
2. 导入所有步骤保持白色同壳布局，右栏主动作固定底部并与摘要保留留白。
3. 再次插卡只预填，只有点击“开始只读预检”才扫描。
4. 预检清楚区分新增、已存在、改后缀、日期未知和无法读取，且不提供逐文件勾选。
5. “确认并导入…”先显示文件数、容量和目标的最终确认，不能直接复制。
6. 空间只在执行前统一检查一次；不足时零创建并显示可用、需要和缺少容量。
7. 正在导入页不在验证和发布完成前计为新增成功；取消只停止未发布部分。
8. 拔卡或重启不会静默继续；只有原卡验证通过且用户确认后才恢复。
9. 导入完成、部分完成、取消和需要处理使用不同报告状态；旧结果不可编辑。
10. 设置页包含照片文件夹、预览缓存、Photoshop 和操作记录四组。
11. 缓存默认 32 GB、最大 64 GB；位置或容量点击后必须确认，取消不改变设置。
12. 设置页没有手动清理缓存；旧缓存仅由应用按安全规则自动渐进淘汰。
13. Photoshop 首次选择、重新选择、配置失效和验证失败都有明确状态，失败不覆盖有效配置。
14. 原图库重连与新图库切换使用不同确认文案；新图库不继承旧状态。
15. 删除问题支持安全重试、取消剩余意图或先重新扫描，绝不提供“标记为成功”。
16. 历史扫描、导入和删除报告只能从完成页、待删除问题页或设置中的操作记录进入；顶栏无常驻报告页签。
17. 普通 UI、确认框和报告均不展示 Root/Library/Photo/Asset/Job/Attempt/Step 等内部 ID、卷 GUID、文件 ID、哈希或 capability。
18. 1440 × 900、1100 × 700、125% 与 150% DPI 下关键摘要、动作、错误和长路径均可访问。
19. 共享顶栏的“设置”是键盘可达的非页签工具按钮；返回时恢复合法来源路由、Photo 和焦点，首次未绑定 Root 时不能绕过绑定门。
20. 首次/新图库全量扫描与原 Root 增量扫描使用不同状态和动作；取消、失败、完成、进入图库及返回发起上下文均可验收，扫描报告不暴露内部 ID。
21. 活动 Import 时删除执行禁用，活动 Recycle 时导入执行禁用；共享状态条能返回进行中任务。预检离开必须确认取消，执行页离开不隐式取消。
22. 执行前刷新若改变未解决项的跳过/新增/冲突分类、安全名称、最终目标位置或单文件计划字节，必须回到预检确认页并由用户确认最终计划代次；计划字段未变时可在同一已确认代次下产生新的验证、空间检查与重试。只有待执行代次确认且本轮刷新一致后才执行本次唯一的自动空间检查。
23. 启动恢复按 Import、可重试删除和结果不明删除分别呈现动作；结果不明仍可取消尚未执行的剩余意图，但不能改写未知事实。

## 8. v1 不包含

- 历史图库重复文件清理；
- 画面相似、连拍相似或不同导出版本识别；
- 手动 JPG/RAF 配对或拆分；
- 应用内回收站、永久删除或报告结果编辑；
- 手动清理缓存；
- 完整 RAW 解码、评分或专业筛片工作流。
