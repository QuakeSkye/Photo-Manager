# 本地 Fuji 照片管理器 v1：导入“选择位置”页 UI 补充规格

- 状态：书面规格已由用户确认
- 日期：2026-07-29
- 上位产品规格：`2026-07-28-local-photo-manager-design.md`
- 上位视觉规格：`2026-07-28-local-photo-manager-ui-design.md`
- 后续流程规格：`2026-07-29-local-photo-manager-operations-ui-design.md`
- 覆盖范围：导入流程第 1 步“选择位置”及其预检触发边界

## 1. 设计结论

导入流程第 1 步由“选择来源”改名为“选择位置”。页面必须在同一处明确展示并允许选择：

1. 内存卡来源文件夹；
2. 电脑端 Fuji 图库根目录。

来源目录是本次扫描的子树。目标目录是应用当前绑定的、持久保存的 `FujiLibrary` Root，不是仅对本次导入有效的临时目标。首次选择后应用记住目标；用户以后仍可在每次进入导入页时更改，但更改等同于重新绑定当前 Fuji 图库。

页面采用上下排列的“双路径选择区”。不使用左右并排路径，不把目标目录隐藏在弹窗入口中。这样可以完整显示较长的 Windows 路径，并把本步骤的两个核心决定集中在同一视觉区域。

## 2. 信息架构

导入页继续复用已确认的 A 方案“同壳工作页”：

```text
┌──────────────────────────────────────────────────────────────────┐
│ FUJI 图库  图库 [待删除 N] │ 导入照片        设置       返回图库 │
├────────────┬──────────────────────────────────────┬──────────────┤
│ 导入步骤   │ 选择导入位置                         │ 只读预检     │
│            │                                      │              │
│ 1 选择位置│ 内存卡来源文件夹                     │ 此步骤不会   │
│ 2 预检确认│ [卷与完整路径]              [更改]   │ 复制文件     │
│ 3 正在导入│                                      │              │
│ 4 导入报告│ Fuji 图库根目录                      │              │
│            │ [完整路径]                 [更改]   │ [取消]       │
│            │ 新照片预计保存位置                  │ [开始预检]   │
└────────────┴──────────────────────────────────────┴──────────────┘
```

左侧步骤栏只负责显示流程位置，不重复路径、安全策略或格式说明。右侧操作栏只显示本步性质和底部操作，不重复中央区域已经展示的来源、目标、格式或扫描范围。

顶栏复用全应用共享导航规则，图中的 `[待删除 N]` 是条件项而不是导入页固定入口：只有 `PendingDeleteSummary` 中至少有一个有效标记或仍需处理的问题 Photo 时才显示，并以逻辑 Photo 数量作为 `N`；数量为 0 时整项隐藏，不保留禁用按钮或空白占位。进入导入页不会强制显示该入口，也不会改变已有待删除状态；点击可见入口进入待删除复核页。“设置”是非页签工具按钮，不计入照片视图数量；键盘与返回焦点规则遵守核心 UI 规格。

## 3. 中央双路径选择区

### 3.1 内存卡来源文件夹

来源区域显示：

- 标题“内存卡来源文件夹”；
- 已识别卷名，例如 `FUJIFILM_SD`；
- 用户选择的完整路径，例如 `E:\DCIM\100_FUJI`；
- “选择文件夹”或“更改”按钮；
- 一句紧邻路径的辅助文字：“将递归扫描此文件夹及其子目录”。

首次没有来源时显示空路径状态并突出“选择文件夹”。同一张已可靠识别的内存卡再次插入时，只预填已保存的相对文件夹；用户仍可更改。插卡、识别成功、打开导入页或完成预填都不得自动扫描。只有用户点击“开始只读预检”后，应用才递归扫描所选子树。

如果应用无法可靠确认是原内存卡，即使盘符、卷标和目录名相同也不自动预填为可用来源；界面显示“请重新选择来源文件夹”，完成只读复核后才允许预检。

### 3.2 Fuji 图库根目录

目标区域显示：

- 标题“Fuji 图库根目录”；
- 当前绑定的完整路径，例如 `G:\照片`；
- “选择文件夹”或“更改”按钮；
- 一句紧邻路径的辅助文字：“首次选择后记住；更改会重新绑定当前 Fuji 图库”。

目标选择不是本次导入的临时参数。用户确认更改并完成身份验证后：

- 能证明卷身份与根目录身份都与原图库一致时，显示“已重新连接原图库”，保留原索引、浏览位置、标记与历史。
- 无法证明为原图库时，确认框明确显示“这将切换到一个新的 Fuji 图库”；确认后建立新图库上下文并启动首次全量扫描，旧图库状态保留但不迁移。
- 盘符、卷标、目录名或路径相似不能作为继承原状态的依据。

重新绑定后的扫描行为不得由实现临时决定：原图库可靠重连只启动增量扫描，并允许使用既有索引返回图库；首次绑定或切换到新图库必须进入操作 UI 规格定义的全量扫描门，在扫描完成前不能显示虚假的空图库。从导入页发起的新图库切换在全量扫描完成后返回“选择位置”并重新验证来源、目标和预检条件；用户也可以从完成摘要显式进入图库。

### 3.3 保存位置预览

目标区域下方使用一段普通内联文字显示目录规则，不再创建独立信息卡：

```text
JPG → G:\照片\2026\20260729\
RAF → G:\照片\2026\20260729\raw\
```

预览使用示例拍摄日期说明结构，不表示预检已经完成。没有可靠拍摄日期的文件将进入 `Unknown-Date`；该说明可放在预览下方的次要文字中。

## 4. 删除的信息

中央区域原有以下四张小卡片全部删除：

- 扫描范围；
- 识别格式；
- 源卡保护；
- 下一步。

这些规则仍是产品行为，但不再拆成四个并列视觉单元。必须保留的信息通过路径旁的一句话、右侧“此步骤不会复制文件”以及后续预检结果表达。

右侧原有的来源文件夹、递归子目录、识别格式和源卷权限指标列表也删除，避免与中央路径区重复。

## 5. 操作与状态

右侧操作栏只保留：

- 标题“只读预检”；
- 一句说明“此步骤不会复制文件”；
- 底部“取消”和“开始只读预检”按钮。

只有来源和目标都已选择且当前验证有效时，“开始只读预检”才可用。点击后只进入预检，不自动开始复制。

同一时间只允许一个会改变照片文件系统的任务。存在未完成的 Root 扫描、导入、删除、恢复协调或缓存切换时，来源和目标的“更改”按钮保持可见但不可用，并就地说明“请先完成或取消当前任务”；限制由 Rust 强制执行，不能只依赖按钮禁用。全量扫描只有在用户确认取消并进入“扫描已取消”后才允许重新选择 Root。

更改目标目录的流程：

1. Rust 打开原生文件夹选择器；
2. 应用只读验证候选目录、卷与 Root 身份；
3. 根据身份结果显示“重新连接原图库”或“切换到新的 Fuji 图库”的影响摘要；
4. 用户确认后原子保存新绑定，并按身份结果启动增量扫描或首次全量扫描；
5. 原 Root 增量扫描可在既有索引上继续；首次/新图库全量扫描必须先经过扫描门；
6. 扫描达到允许返回的状态后回到选择位置页，重新验证来源、目标并重新计算预检条件。

取消确认不得改变现有 `FujiLibrary` 绑定。

## 6. 目标目录与新增照片规则

用户选择的是图库根目录。新增照片不直接平铺在根目录，也不创建“本次导入”批次目录。

有可靠拍摄日期时：

```text
FujiRoot/YYYY/YYYYMMDD/DSCF1234.JPG
FujiRoot/YYYY/YYYYMMDD/raw/DSCF1234.RAF
```

无可靠拍摄日期时：

```text
FujiRoot/Unknown-Date/DSCF1234.JPG
FujiRoot/Unknown-Date/raw/DSCF1234.RAF
```

只有用户完成预检并在下一步最终确认导入后，应用才创建缺少的日期目录并发布新文件。选择位置和只读预检阶段不创建目录、不复制文件。

应用不整理、移动或重命名目标 Root 中的历史照片。只有新导入文件使用标准目录规则。

## 7. 验证与错误处理

目标 Root 必须满足上位产品规格中的能力约束：

- 位于本机 NTFS；
- 不是内存卡所在卷；
- 与来源文件夹、任何已记录内存卡来源、缓存父目录/专属缓存目录及固定应用数据目录均不存在正向或反向包含；
- 不是 reparse point 或不受支持的挂载路径；
- Root 身份可可靠记录并在重开时验证。

来源目录也必须相对当前图库、缓存和应用数据目录执行双向不重叠及卷能力检查。任何 Root 扫描、导入、删除、恢复协调或缓存切换处于未终结状态时，不允许提交来源、图库或缓存的新绑定；已取消或失败并到达可处理状态的扫描按操作 UI 规格提供明确的重新选择入口。

如果候选目标不符合条件，保持原有 Fuji 图库绑定不变，并在目标路径区域内显示具体原因。不得只显示“选择失败”。

如果已绑定目标离线或身份变化：

- 路径区域显示“需要重新选择”；
- “开始只读预检”不可用；
- 应用不得把同盘符的新卷当作原 Root；
- 用户重新选择后，必须先完成卷身份与 Root 身份验证。

来源文件夹不存在、内存卡身份不符或来源与目标发生能力冲突时采用同样的就地错误表达，不弹出连续通知。

## 8. 视觉与可访问性

- 复用核心 UI 规格的白色、浅灰、字体、边框与按钮 token。
- 两个路径区域使用一个连续主面板中的上下分区，不拆成多个阴影卡片。
- 完整路径允许换行；不得只保留末尾文件夹名导致用户无法判断盘符和层级。
- `RootId`、`LibraryId`、卷 GUID、文件 ID、内容哈希和 capability 名称属于内部实现信息，普通界面不得展示。界面只显示用户可理解的卷名、完整目录路径以及“已连接”“需要重新选择”“无法使用此目录”等状态文字。错误说明同样不得要求用户理解内部 ID；内部标识只允许进入开发诊断日志。
- “更改”按钮使用普通样式；“开始只读预检”使用深色主按钮；本页没有危险红色操作。
- 键盘焦点、无效状态和当前绑定状态不能只依赖颜色。
- 在 1100 × 700 最小窗口下，两个路径、保存位置预览和底部操作必须仍可访问；必要时只允许中央内容滚动。

## 9. 验收条件

1. 页面和左侧第 1 步均显示“选择位置”。
2. 来源文件夹与 Fuji 图库根目录都能从该页选择或更改。
3. 目标更改明确表示重新绑定，而不是仅本次生效。
4. 页面不再显示“扫描范围、识别格式、源卡保护、下一步”四张小卡片。
5. 右侧不重复显示路径、格式、递归和权限指标。
6. 页面明确预览 `YYYY/YYYYMMDD/` 与 `raw/` 目录规则。
7. 未知日期明确进入 `Unknown-Date`。
8. 选择位置和预检阶段不会创建目标目录或复制文件。
9. 非本机 NTFS、源目标同卷、Root 重叠和身份不可靠的目标被拒绝，且原绑定不变。
10. 普通界面不显示 `RootId`、`LibraryId`、卷 GUID、文件 ID、内容哈希或 capability 名称。
11. 1440 × 900、1100 × 700、125% 与 150% DPI 下信息层级清楚，长路径可辨认。
12. 导入页共享顶栏在待处理数量为 0 时不显示待删除入口；数量大于 0 时显示“待删除 N”，进入导入页本身不会改变该状态。
13. 再次插入同一张卡只识别并预填来源；未点击“开始只读预检”前没有递归扫描。
14. 可靠重连原图库时保留状态；选择不同图库时明确提示并且不迁移旧状态。
15. 未终结 Root 扫描、写任务或恢复协调期间不能更改来源、图库或缓存绑定，且界面说明原因；必须先按规定取消或完成当前任务。
16. 来源、图库、缓存和应用数据目录之间的正向与反向重叠均被拒绝。
17. 共享顶栏的“设置”是非页签工具按钮，键盘可达；进入和返回不会把设置变成第三个照片视图。
18. 原图库重连使用既有索引并执行增量扫描；首次/新图库切换执行全量扫描，完成前不显示虚假空图库，导入页返回后重新验证预检条件。

## 10. 本补充规格之外

- 不改变预检分类、重复判断、同名后缀和 no-overwrite 发布规则；
- 不增加每次导入的临时目标；
- 不提供自定义日期目录模板；
- 不整理历史图库；
- 预检、确认、进行中、恢复和报告页面由 `2026-07-29-local-photo-manager-operations-ui-design.md` 冻结。
