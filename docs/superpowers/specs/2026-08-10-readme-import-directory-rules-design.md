# README 导入目录与目标路径说明设计

- 日期：2026-08-10
- 状态：已确认

- 关联设计：`docs/superpowers/specs/2026-08-10-readme-design.md`

## 1. 目标

在 README 的“基本使用流程”之前新增“目录要求与导入路径”章节，帮助普通用户明确区分导入来源目录与 Fuji 图库根目录，了解两类目录的安全限制，并能预先判断照片导入后的实际保存位置。

## 2. 章节结构

新增章节采用“角色说明 + 限制列表 + 路径示例”的组织方式，依次包含：

1. 两类目录的角色
2. 导入来源目录要求
3. Fuji 图库根目录要求
4. 导入后的路径规则与示例
5. 重复文件和名称冲突规则

章节不使用界面截图，不重复开发环境、构建命令或完整安全架构说明。

## 3. 两类目录的角色

README 使用以下术语：

- **导入来源目录**：用户选择的内存卡或其他来源文件夹。应用只递归扫描这个目录及其子目录。
- **Fuji 图库根目录**：当前绑定的本地图库，也是新增照片的最终保存根目录。

必须明确说明：导入不会复制来源目录的原有层级。来源文件在图库中的目标路径由可靠的 EXIF 拍摄日期、媒体类型和名称冲突结果决定。

## 4. 导入来源目录要求

README 应准确说明：

- 递归处理所选目录子树中的 JPG、JPEG 和 RAF；其他扩展名被忽略并计入预检摘要。
- 不跟随符号链接、junction 或其他 reparse point。
- 应用不会向来源卷写入缓存、日志、临时文件或其他内容，也不会删除、移动、格式化或弹出来源介质。
- 来源卷不能与当前 Fuji 图库位于同一个卷。
- 来源卷不能承载应用数据、当前或历史活动缓存 Root，以及应用必须写入的其他位置。
- 选择来源后，整个来源卷会被登记为永久拒写；以后不能把该卷绑定为 Fuji 图库或其他应用写入位置。这个边界大于用户所选的来源子目录。
- 如果预检期间来源目录身份或照片文件发生变化，本次计划失效，用户需要重新预检。

文档不声称来源卷必须为 NTFS；NTFS 强身份要求属于导入目标图库。

## 5. Fuji 图库根目录要求

README 应准确说明：

- 浏览可以读取已绑定图库，但执行安全导入要求当前图库位于可可靠识别的 NTFS 卷。
- 图库应是稳定的普通目录，不能与应用数据目录或其他已登记 Root 重叠。
- 曾经登记为导入来源的卷不能再作为 Fuji 图库。
- 执行导入时，来源卷与图库卷必须不同。
- 目标可用空间必须至少为本次新增字节数加上 `max(10 GiB, 目标卷总容量的 2%)` 安全余量，否则导入不会开始。
- 应用不会为了统一结构而移动、重命名或重排已经存在的历史图库文件；目录规则只适用于新导入副本。

## 6. 导入路径规则

若可靠拍摄日期为 `YYYY-MM-DD`：

```text
JPG/JPEG → <图库根目录>\YYYY\YYYYMMDD\<原文件名>
RAF      → <图库根目录>\YYYY\YYYYMMDD\raw\<原文件名>
```

示例：图库根目录为 `D:\Photos\Fuji`，照片日期为 `2026-08-10`：

```text
D:\Photos\Fuji\2026\20260810\DSCF1234.JPG
D:\Photos\Fuji\2026\20260810\raw\DSCF1234.RAF
```

若无法取得可靠日期：

```text
JPG/JPEG → <图库根目录>\Unknown-Date\<原文件名>
RAF      → <图库根目录>\Unknown-Date\raw\<原文件名>
```

示例：

```text
D:\Photos\Fuji\Unknown-Date\DSCF1234.JPG
D:\Photos\Fuji\Unknown-Date\raw\DSCF1234.RAF
```

对于可靠配对的 JPG/RAF，若只有一端具备日期，则该日期用于整组目标路径；若两端可靠日期不在同一天，则保守拆分并分别规划。

## 7. 重复与重名规则

- 只有来源和目标经过稳定身份复核、完整哈希以及逐字节比较并确认相同，才会作为重复文件跳过。
- 已有导入历史不能单独作为跳过依据。
- 目标名称已存在但内容不同时不会覆盖；应用查找完整名称族并使用第一个可用的 `_2`、`_3` 等数字后缀。
- 能作为一组规划的 JPG/RAF 尽量使用相同数字后缀。
- 保留来源文件名和扩展名大小写；添加后缀时形式为 `<原主名>_<数字>.<原扩展名>`。
- 如果预检后目标文件或名称族发生变化，旧计划不能静默改名或扩大复制范围，必须重新确认。

## 8. 验收标准

README 增补完成后应满足：

1. 明确区分来源目录与图库根目录，不把“导入目录”用作含糊术语。
2. 清楚说明所选来源子树与整个来源卷安全边界的区别。
3. 给出有日期、无日期、JPG/JPEG 和 RAF 四类目标路径规则。
4. 明确说明来源原目录层级不会原样复制，现有历史图库也不会被重新整理。
5. 包含不同卷、NTFS 目标、永久来源卷拒写和空间余量要求。
6. 重复、重名和配对后缀说明与当前路径规划源码一致。
7. 不引入截图、占位符或无法由当前源码验证的行为。
