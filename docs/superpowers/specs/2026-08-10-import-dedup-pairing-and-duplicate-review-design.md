# 导入去重、配对与历史重复复核设计

## 背景

现有 Fuji 图库允许历史照片位于任意普通子目录；只有新导入副本使用 `YYYY\YYYYMMDD` 和 `raw` 目录规则。当前导入预检只从 `ImportHistory` 和精确目标日期目录的名称族查找重复候选，漏掉了图库其他目录中同名、同大小且拍摄时间相容的现有 Asset。历史照片若放在近似日期目录，内存卡再次导入时会被复制到精确日期目录，形成内容完全相同的第二份文件。

重复副本又使历史 JPG/RAF 配对失去“候选唯一”条件。另一个独立缺陷是：同一 ImportGroup 中一端被完整重复证明跳过、另一端新复制时，当前配对协调只认识两端都具有 `PublishedFact + IndexedFact` 的情况，无法把跳过端的既有 Asset 与新增端配对。

本设计先修复未来导入和配对，再增加完全由用户启动、选择和确认的历史重复复核。任何阶段都不得自动删除、移动、重命名或选择照片。

## 目标

- 按既有规格从整个当前图库发现导入重复候选，避免因历史目录不规范产生新副本。
- 保留稳定句柄、完整 SHA-256、逐字节比较和前后身份复核；数据库候选不能直接授权跳过。
- 使用不可变事实统一表示 Copy 和 Skip Step 最终对应的 Asset。
- 正确支持 `Copy + Copy`、`Copy + Skip`、`Skip + Copy` 和 `Skip + Skip` JPG/RAF 导入组配对。
- 提供手动启动的历史重复检测，只认定逐字节完全相同的物理文件。
- 清楚展示每组照片有几份 JPG、几份 RAF、是否两种格式都重复以及全部文件位置。
- 支持按位置整套选择或单独选择 JPG/RAF；不自动勾选。
- 用户选择的副本先进入待删除复核，最终只通过 Windows 回收站处理。
- 真正回收前再次证明仍有一份未选择删除、完整且逐字节相同的保留副本。
- 完成已确认的图库顶部、底部状态栏和右侧照片信息布局优化。

## 非目标

- 不自动清理历史重复文件。
- 不自动移动、重排或规范化历史图库目录。
- 不把相同画面、重新压缩、重新导出或编辑后的照片视为本功能的重复文件。
- 不实现相似照片、感知哈希、AI 识图或保留质量评分。
- 不引入常驻的全图库完整哈希后台任务。
- 不提供永久删除、静默回收或绕过待删除复核的入口。
- 不因路径更规范就假定内容相同。

## 总体方案

采用显式不可变“导入成员解析事实”方案：

```text
全图库候选发现 -> 当前完整重复证明 -> Copy 或 Skip
                                      |
                    +-----------------+-----------------+
                    |                                   |
              PublishedIndexed                  SkippedDuplicate
                    |                                   |
                    +---- ImportAssetResolutionFact ----+
                                      |
                              ImportGroup 配对协调
```

候选发现、重复证明、Asset 解析和 Photo 配对保持四个独立边界：

- 候选发现只减少需要读取的文件数量。
- 重复证明只回答两个当前路径对象是否逐字节相同。
- Asset 解析把已完成 Step 绑定到当前 Catalog Asset。
- 配对协调只消费两端完整、无冲突的解析事实。

历史重复检测复用同一稳定读取与逐字节证明组件，但使用独立的扫描运行和等价证明记录。旧检测结果不是删除授权。

## 一、全图库导入候选发现

### 候选顺序

每个来源文件按以下顺序收集目标候选：

1. `ImportHistory` 中同来源身份或既有内容指纹指向的当前 Asset。
2. 当前图库中原始文件名、扩展名、大小相同且拍摄时间相容的 Present Asset。
3. 精确目标日期目录中原名、`_2`、`_3` 等完整名称族的普通文件。

候选按规范 path key 去重。历史图库中的同名候选可以位于任意日期或自定义子目录。v1 仍不承诺发现应用外改名且不再匹配来源原始文件名的历史副本；历史重复检测可以通过内容发现这些文件，但导入预检不为此读取整个图库。

### 候选查询键

新增按 AssetVersion 派生的候选查询键，保存以下必需字段：

- `asset_id + asset_version`；
- 大小写折叠后的原始文件名；
- 大小写折叠后的扩展名；
- 文件大小；
- 可空的可靠拍摄本地时间键；
- Root、Binding 和当前 path key。
- 查询键格式版本。

该表是可重建查询索引，不是内容或跳过事实。Catalog 建立新 AssetVersion 时同步写入对应查询键；迁移后由只读 Catalog 协调为当前 Present Asset 补齐。查询键缺失或过期只会减少优化，不能导致错误跳过。

拍摄时间相容定义为：双方都有可靠值时必须完全一致；任一端缺失时允许进入候选集合，最终仍以完整内容证明决定是否重复。

### 当前重复证明

每个候选继续执行现有强证明：

1. 从受约束 Root 打开拒绝共享写入和删除的稳定只读句柄。
2. 确认两端大小相同。
3. 完整读取并计算 SHA-256。
4. SHA-256 相同后逐字节比较。
5. 比较前后验证两端 Root、Binding、volume、path key、file ID、大小和 mtime 不变。
6. 原句柄保持打开时重新从计划路径打开，证明路径仍指向同一对象。

任一步失败均不得判定 Skip。来源变化使本次预检或验证失效；目标候选变化使该候选不可用，并按现有计划刷新规则决定继续搜索、形成 Copy 或要求用户重新确认。

## 二、导入成员解析事实

新增不可变 `ImportAssetResolutionFact`，必需字段为：

```text
resolution_fact_id
step_id                 UNIQUE
asset_id
asset_version
resolution_kind         PublishedIndexed | SkippedDuplicate
indexed_fact_id         PublishedIndexed 时非空
duplicate_proof_id      SkippedDuplicate 时非空
evidence_snapshot_id
resolved_at
```

约束保证：

- 每个 Step 最多一个解析事实。
- 两种 evidence owner 恰好选择一种，不能全空或混填。
- `PublishedIndexed` 必须引用该 Step 的 `ImportIndexedFact`。
- `SkippedDuplicate` 必须引用该 AttemptStep 的 Execution DuplicateProof 及其 PathBindingProof。
- Asset、AssetVersion 和 evidence snapshot 必须解释同一个当前目标对象。

### 新复制端

新文件完成 no-replace 发布并由 Catalog 索引时，在提交 `ImportIndexedFact` 的同一 SQLite 事务中写入 `PublishedIndexed` 解析事实。若索引事实已经存在而解析事实因旧版本或崩溃缺失，启动协调只从完整不可变事实链补建。

### 重复跳过端

执行期重新完成 DuplicateProof、PathBindingProof 和 `SkippedDuplicate` 后，将目标路径解析到当前 Present Asset：

- 目标已建档时，复核当前 AssetRevision 与 target evidence snapshot 一致后写入解析事实。
- 目标尚未建档时，通过只读 Catalog 观察建档，再写入解析事实。
- 进程在二者之间中断时，启动协调根据执行期证明和当前 Catalog 观察补建；不得再次复制。
- 当前目标无法再映射到同一 Asset 时保持未解析并进入需要关注，不猜测其他同内容文件。

## 三、ImportGroup 配对协调

配对协调按 ImportGroup 读取两端解析事实，不再要求两端都具有 PublishedFact。有效组合包括：

```text
JPG Copy + RAF Copy
JPG Copy + RAF Skip
JPG Skip + RAF Copy
JPG Skip + RAF Skip
```

创建 `SameImportGroup` PairEvidence 前必须确认：

- ImportGroup 恰好一个 JPG Step 和一个 RAF Step。
- 两个 Step 各有一个有效解析事实。
- 两个 Asset 当前均为 Present，角色正确且不是同一 Asset。
- 当前 AssetRevision 与各自 evidence snapshot 一致。
- 两端可靠拍摄日期不冲突。
- 两个 Asset 未被其他冲突的活动配对占用。

显式 SameImportGroup 证据优先于历史同名候选的歧义，可把本次明确解析的两个 Asset 合并为一个 Photo。图库中其他重复 Asset 仍保持独立；协调器不得据此猜测它们的对应关系。

已有导入链仅在上述证据完整时补建解析和配对事实。不完整旧数据保持拆分。

## 四、手动历史重复检测

### 启动与调度

重复检测只在用户进入重复文件页面并点击“开始检测”后运行。打开页面、应用启动、普通扫描结束或导入完成均不得自动开始完整哈希。

重复检测与导入、回收、全量/增量图库扫描共享 I/O 调度和互斥门，避免对机械硬盘并发执行多个全盘读取任务。浏览和缓存读取继续使用现有优先级策略。

检测显示当前阶段、已检查文件数、候选数、当前相对路径和取消按钮。取消后的 Run 记录为 Cancelled，但不发布可操作的半成品结果。

### 检测算法

1. 枚举当前 Library 中全部 Present JPG/RAF Asset。
2. 按媒体角色和文件大小分桶；只有一个成员的桶直接跳过内容读取。
3. 对候选使用稳定只读句柄计算完整 SHA-256，并保存前后身份观察。
4. 对哈希相同的成员，以一个锚点和其他成员逐字节比较。
5. 只有字节相同且全部身份稳定的成员进入同一个等价集合。

JPG 与 RAF 永远分别证明内容等价。界面只在以下任一正向关系成立时，把 JPG 等价集合与 RAF 等价集合聚合为便于复核的逻辑照片族：

1. 两个集合中存在当前同属一个活动 Photo 的 JPG/RAF 成员。
2. 大小写折叠后的文件名主体相同、可靠拍摄时间完全一致、相机信息不冲突，并且在本次结果中 JPG 集合和 RAF 集合互为唯一候选。

任一条件存在歧义时分别显示为 JPG-only 和 RAF-only 结果卡。展示聚合不是删除授权，每个物理文件仍由自己的等价证明保护。

必需记录包括：

- `DuplicateScanRun`：Library、RootBinding、catalog revision、状态、计数和时间。
- `DuplicateFileObservation`：AssetVersion、文件身份前后快照和完整哈希。
- `DuplicateEquivalenceSet`：媒体角色、内容摘要、成员数和总字节。
- `DuplicateEquivalenceProof`：锚点、成员、逐字节相同结果和证据快照。

所有证明只追加，不修改旧事实。

### 结果有效期

重复结果不按墙上时间过期，也不因应用重启自动过期。Run 绑定完成时的 RootBinding 和 library catalog revision。以下变化递增 catalog revision 或直接使结果失效：

- 导入发布新 Asset。
- 回收导致 Asset 缺失。
- 扫描发现 Asset 新增、缺失、路径、file ID、大小或 mtime 变化。
- 当前图库 Root 或 Binding 改变。
- 打开结果或建立删除标记时发现证据对象身份变化。

一次没有观察到 Asset 变化的普通扫描不使结果过期。结果失效后清空尚未提交的界面勾选，旧证明保留审计用途但不能建立新删除标记。

## 五、保留建议与选择

每个等价集合至少保留一份。系统只显示可解释的“建议保留”，不自动勾选任何删除项。

只有当前在线、可读且身份与检测结果一致的文件才有资格成为建议保留项。在合格文件中按以下顺序确定：

1. 路径符合 `YYYY\YYYYMMDD` 或 RAF 的 `YYYY\YYYYMMDD\raw` 规则，且目录日期与可靠 EXIF 日期一致。
2. 路径较短。
3. 规范化路径字典序，作为确定性最终平局规则。

用户可以：

- 选择某个位置下的整套重复 JPG/RAF。
- 展开后仅选择 JPG 或仅选择 RAF。
- 更换实际保留项。
- 在资源管理器中查看每个文件。

界面和数据库都禁止选择一个等价集合中的全部成员。

## 六、待删除与保留副本保护

`DeletionMark` 扩展为两种范围：

```text
WholePhoto       现有 D 标记，冻结当前 Photo 的全部 JPG/RAF 成员
DuplicateSubset  重复清理，只冻结用户明确选择的 Asset
```

旧 Mark 默认且始终解释为 `WholePhoto`。普通图库中的 D/R 语义不改变。同一 Photo 的活动 Mark 继续唯一；修改重复选择时释放旧 Mark 并创建新的不可变 Mark，不改写旧快照。

每个 `DuplicateSubset` 的选中 Asset 快照必须绑定一个未选中的同角色保留 Asset、等价证明和保留端身份快照。加入待删除前重新读取选中端与保留端，完成完整哈希、逐字节比较和身份复核。只有验证成功的选择才能建立 Mark。

待删除页把来源标记为“重复清理”，逐项显示：

- 将回收文件的完整路径和所在目录。
- JPG、RAF 或整套状态。
- 对应保留副本的完整路径。
- 文件数、每项大小和合计大小。

点击“移入 Windows 回收站”后，执行前再次完成以下验证：

- 选中 Asset 仍与 Mark 快照一致。
- 保留 Asset 当前存在、在线、未被同一 Batch 选择。
- 两端仍完整哈希相同且逐字节一致。
- 当前 Root、Binding、路径和 file ID 均与证明一致。

任一条件失败时对应项进入 `NeedsAttention`，不调用 Shell。执行仍只使用 Windows 回收站；没有永久删除或自动重试降级。成功或部分失败后触发定向重扫，更新 Asset presence、Photo 配对和重复结果。

## 七、重复复核界面

图库顶部工具按钮顺序为：

```text
导入照片 -> 重复入口 -> 设置
```

重复入口状态为：

- 从未检测：`检查重复`。
- 当前有效结果存在：`重复文件 N`，N 为可复核逻辑照片族数量。
- 结果失效：`重复检查过期`。

一次有效检测未发现重复时，入口恢复为低强调的 `检查重复`，重复页面保留“上次检测未发现重复”的完成摘要。再次点击只进入页面，不自动扫描。

点击 `重复检查过期` 只进入页面并显示失效原因，不自动扫描；用户仍需点击“开始检测”。

检测完成后的摘要显示重复集合数、仅 JPG 重复、仅 RAF 重复、两种都重复、冗余副本数和可释放空间。冗余副本数为每个媒体等价集合 `成员数 - 1` 的总和；可释放空间为每个等价集合 `单文件字节数 × (成员数 - 1)` 的总和，只表示保留一份时的理论上限，不代表已经选择删除。

每个照片族明确显示：

```text
JPG：3 份（重复 2 份）
RAF：2 份（重复 1 份）
状态：JPG 与 RAF 都有重复
```

展开后按位置套组列出建议保留和其他位置。每个物理文件显示完整路径、目录、大小、拍摄时间、当前配对状态和资源管理器入口。证据失效或文件离线时禁用选择。

点击“加入待删除”前显示不可跳过的确认摘要，列出每个删除路径、格式或整套状态、对应保留路径、文件数量和总大小。该动作只建立 Mark，不移动文件。

## 八、图库界面布局优化

### 图库更新状态

移除照片区域顶部悬浮的增量扫描横条。扫描进行时，底部状态栏中央原快捷键位置显示紧凑入口：

```text
正在更新图库 · 已检查 931 个文件 · 查看进度
```

没有扫描运行时底部中央留空。左侧照片位置和右侧待删除状态保持现有含义。

原底部快捷键说明移动到右侧“标记待删除”按钮下方，显示：

```text
← → 浏览 · D 标记 · R 撤销
D 只保存复核标记，不会移动或修改照片。
```

键帽文字必须水平和垂直居中。

### 时间与文件信息

- 字段 `容量` 改名为 `照片大小`。
- 有可靠 EXIF 时间时，只显示 `拍摄日期`、`相机本地时间` 和 `照片大小`。
- 删除“按相机记录的本地时间显示”说明。
- 无可靠 EXIF 时间时，不显示日期、时间或“未记录”占位，只显示 `照片大小`。
- 删除 `文件时间` 字段及其说明；文件时间不再出现在照片 Inspector。

### Inspector 宽度与动作区

右侧 Inspector 使用 `clamp(300px, 20vw, 360px)`，同时保证 1100 px 最小应用宽度下中央照片区域仍可用。元数据标签列从 86 px 缩短为 58 px；镜头值使用 10 px 独立单行样式。以 `SIGMA 18-50mm F2.8 DC DN | Contemporary 021` 作为不换行验收样例。

“用 Photoshop 打开 RAF”按钮使用独立 class，字体为 12 px 并禁止换行，不能影响文件位置、待删除或其他全局按钮字号。D 键帽使用明确的 grid/flex 居中和 `line-height: 1` 规则。

布局在 1100、1366 和 1920 px 应用宽度，以及 Windows 100%、125% 和 150% 显示缩放下验证。

## 九、错误处理与恢复

- 全图库候选查询失败时不得降级为数据库哈希直接跳过；预检返回可操作错误或把候选视为不可证明。
- 来源身份变化使预检/Validation 失效，不继续复制。
- 目标候选变化后重新计算 Copy/Skip、后缀和字节；变化影响已确认计划时要求重新确认。
- 解析事实或配对事务失败不能回滚已安全发布的文件；任务报告进入错误或需要关注。
- 重复扫描读取错误记录到 Run，其他候选可继续；只有完整成功的等价证明可展示为可选择。
- 重复结果页打开期间发生 catalog revision 变化时立即清除未提交选择并显示过期状态。
- Mark 建立或回收前的保留证明失败时不删除任何无法重新证明安全的文件。
- Shell 结果未知、回收站不可用或 SQLite 结果提交失败继续使用现有保守停止和恢复规则。

## 十、迁移与兼容

新增 `0010` 迁移，包含：

- AssetVersion 候选查询键及索引。
- `ImportAssetResolutionFact` 及证据链约束。
- Duplicate Run、Observation、Set 和 Proof 表。
- `DeletionMark` 范围和 DuplicateSubset 保留保护事实。
- 支持 WholePhoto 与 DuplicateSubset 的 Batch 复制和一致性触发器。

迁移不得改写照片文件或伪造 AssetVersion。旧 DeletionMark 解释为 WholePhoto。旧 Import Step 的解析事实由运行时协调根据完整链追加；迁移事务本身不根据路径或同名猜测 Asset。

如果新表、触发器、外键或回填协调完整性检查失败，应用进入现有只读安全模式，Import 与 Recycle 保持关闭。

## 十一、测试与验收

### 导入去重

- 历史 JPG/RAF 位于错误日期目录、EXIF 指向另一日期时，内存卡相同文件预检为 Skip，不创建精确日期副本。
- 只有 JPG 位于其他目录时，JPG Skip、RAF Copy 后形成一个 `JPG ✓ / RAF ✓` Photo。
- 只有 RAF 位于其他目录时覆盖反向矩阵。
- 两端 Skip 和两端 Copy 均形成一个可靠配对 Photo。
- 同名、同大小但内容不同仍按完整名称族规划统一后缀。
- 候选在哈希、逐字节比较或路径重开期间变化时不得 Skip。
- 目标未建档时可在只读观察后形成 SkippedDuplicate 解析事实。
- 在 DuplicateProof 提交与解析事实创建之间模拟崩溃，启动协调只补索引/事实，不再次复制。
- 所有测试验证来源和既有目标的字节、大小和 mtime 未被应用修改。

### 历史重复检测

- 两份、三份及更多 JPG/RAF 内容相同文件得到正确总份数和冗余份数。
- 覆盖仅 JPG、仅 RAF、JPG/RAF 都重复以及应用外改名但内容相同的检测。
- 模拟 SHA-256 相同但字节不同，成员不得进入同一等价集合。
- 检测取消、读取错误和身份变化不产生可操作半结果。
- 无 catalog 变化的普通扫描不使结果过期；Asset 或 Binding 变化使结果过期。
- 建议保留规则在相同输入下稳定，且不产生自动勾选。

### 待删除与回收

- 整套选择和单 JPG/RAF 选择生成准确 DuplicateSubset 快照。
- UI 和数据库都拒绝选择等价集合的全部成员。
- 加入待删除前保留端变化时拒绝 Mark。
- Mark 后、Batch 前或 Shell 前保留端缺失、变化、离线时进入 NeedsAttention 且不删除选中端。
- 普通 D/R 和 WholePhoto 回收回归测试保持通过。
- 重复清理项准确显示删除路径和保留路径，部分失败结果不自动选择或重试。

### 界面

- 顶部重复入口位于导入照片右侧，三种状态和手动启动语义正确。
- 增量扫描状态只出现在底部中央，照片区域顶部没有旧横条。
- 快捷键说明位于待删除按钮下方，D 键帽居中。
- 有 EXIF 时只显示拍摄日期、相机本地时间和照片大小。
- 无 EXIF 时只显示照片大小。
- Inspector 不显示文件时间和旧容量标签。
- 指定 SIGMA 镜头样例和 Photoshop 按钮在目标窗口宽度与缩放下保持单行。

自动测试只使用生成夹具或明确可丢弃的副本，不读取、修改或删除用户唯一照片。Windows 回收站冒烟测试使用专用可恢复测试目录。
