# 重复文件精确文件名预筛设计

## 背景

当前重复检测先按媒体角色与文件大小筛选，再对候选计算完整 SHA-256，最后逐字节比较。文件名不参与筛选，因此内容相同但名称不同的文件也会进入重复结果。用户的照片工作流不会重命名文件，希望利用这一稳定约束减少不必要的磁盘读取，同时继续保证待删除流程不会仅凭文件名判断重复。

## 目标

- 使用精确文件名缩小重复检测候选范围。
- 保留完整 SHA-256、逐字节比较和文件身份复核，作为加入待删除前的内容安全证明。
- 准确区分哈希进度与逐字节比较阶段，避免“全部验证完成但仍在比较”的误解。
- 不改变手动启动、待删除页复核和 Windows 回收站流程。

## 候选规则

检测从每个相对路径提取最后一级完整文件名。文件名匹配具有以下语义：

- 忽略所在目录。
- 区分大小写。
- 主文件名和扩展名都必须完全一致。
- JPG 与 RAF 等不同媒体角色不交叉比较。

例如：

| 文件 A | 文件 B | 是否成为文件名候选 |
| --- | --- | --- |
| `A\DSCF2823.JPG` | `B\DSCF2823.JPG` | 是 |
| `A\DSCF2823.JPG` | `B\DSCF2823.jpg` | 否 |
| `A\DSCF2823.JPG` | `B\DSCF2824.JPG` | 否 |
| `A\DSCF2823.JPG` | `B\DSCF2823.RAF` | 否 |

## 检测流程

1. 枚举当前在线图库中的文件。
2. 按“媒体角色 + 区分大小写的完整文件名 + 文件大小”分组。
3. 只有成员数大于一的分组进入候选集合。
4. 对候选文件执行稳定的完整 SHA-256：读取前后都验证文件身份，读取期间支持取消。
5. 按“媒体角色 + 文件名 + 文件大小 + SHA-256”形成哈希组。
6. 哈希组内逐字节比较，并在比较前后重新验证文件身份。
7. 再次计算稳定哈希，只有仍然稳定且至少包含两个成员的等价类才发布为重复结果。

精确文件名只是性能预筛条件，不是删除证据。文件名相同但大小、哈希或字节内容不同的文件直接排除，不进入重复复核，也不创建待删除标记。

## 进度语义

- `候选`：通过媒体角色、精确文件名和文件大小预筛的文件数。
- `已完成哈希`：成功完成稳定 SHA-256 的候选文件数。
- 阶段标题继续区分“正在完整哈希”“正在逐字节比较”和“正在发布结果”。
- 现有“已完整验证”文案改为“已完成哈希”，不再暗示逐字节比较已经结束。

本次不增加逐字节比较计数器，也不为此修改数据库结构。

## 异常与生命周期

- 同名但大小不同：预筛排除，不读取内容。
- 同名同大小但哈希或字节不同：安全排除，不显示为冲突或重复。
- 文件离线、无法读取、身份变化或无法稳定复核：跳过该文件，不发布不完整证明。
- 取消、应用重启后的孤立扫描收尾和发布事务回滚机制保持不变。
- 新规则应用于以后手动启动的检测。历史已发布结果仍有完整内容证明，因此不自动失效；用户重新检测后，新结果按文件名规则替换旧结果。

## 实现边界

- 候选分组和哈希分组显式包含区分大小写的完整文件名。
- 使用路径的最后一级文件名，不把目录加入匹配键。
- 不依赖 Windows 默认的不区分大小写行为，不执行大小写折叠或 Unicode 模糊归一化。
- 不增加数据库迁移，不改变重复结果、保留证明或待删除命令的数据结构。
- 不增加同名冲突页面、相似照片识别、感知哈希或元数据近似匹配。

## 验证

- 不同目录、相同大小写文件名且内容相同：识别为重复。
- 内容相同但文件名不同：不进入候选结果。
- 文件名仅大小写不同：不进入候选结果。
- 同名但大小不同：不进入哈希阶段。
- 同名同大小但内容不同：完成证明后排除。
- JPG 与 RAF 不交叉比较。
- 进度界面显示“已完成哈希”，阶段标题正确显示比较与发布。
- 现有取消、重启恢复、发布事务、待删除证明和回收站流程测试继续通过。

## 非目标

- 不把文件名本身作为重复或删除依据。
- 不检测改名后内容相同的副本。
- 不自动启动重新检测。
- 不修改或移动任何原始照片。
