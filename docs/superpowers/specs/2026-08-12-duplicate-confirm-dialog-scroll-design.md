# 重复复核确认弹框滚动设计

## 问题

“确认加入待删除”弹框会一次渲染全部已选文件。选择数量较多时，弹框高度超过应用窗口，底部“取消”和“加入待删除”按钮被挤出可视区域，用户无法完成确认。

## 设计

- 弹框整体高度不得超过当前窗口扣除安全边距后的可视高度。
- 标题、顶部安全说明、底部文件数量与容量统计、操作按钮始终可见。
- 只有中间的待删除文件列表独立纵向滚动。
- 列表没有足够内容时不显示无意义的滚动条，弹框保持当前紧凑高度。
- 路径内容、删除端与保留端信息、安全确认语义均保持不变。
- 该约束只应用于重复复核的“确认加入待删除”弹框，不改变其他共用 `Modal` 的布局和滚动行为。

## 实现边界

- 为该弹框增加专用样式钩子或列表容器样式，不给所有弹框强制统一高度。
- 文件列表使用可收缩的弹性区域和 `overflow-y: auto`；同时保证长路径可以换行，不产生横向滚动。
- 窄窗口下保留弹框外层安全边距，操作按钮仍在窗口内。

## 验证

- 增加前端测试，确认弹框使用专用滚动布局，文件列表位于该滚动区域内。
- 保留现有删除路径、保留路径和确认动作测试。
- 运行重复复核组件测试、格式检查、类型检查和生产构建。

## 非目标

- 不改变待删除选择、保留证明、数据库标记或 Windows 回收站流程。
- 不增加分页、虚拟列表、搜索或批量修改功能。
- 不改造通用 `Modal` 组件的全部使用方。
