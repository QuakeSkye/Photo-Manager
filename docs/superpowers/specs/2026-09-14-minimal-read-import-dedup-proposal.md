# V3：保留精确预检的最少读取导入与查重设计

初稿：2026-09-14；修订：2026-09-16。状态：设计提案，尚未修改业务实现。用户最终确认保留“精确预检 → 查看结果 → 确认导入”。本版替代 V2 将精确判断放在确认后的方案；文件路径保持不变。

对照：[新旧流程图](D:/A/MyProject/ai/Aifirtst/docs/superpowers/reports/2026-09-14-import-dedup-flow-comparison.md)。问题来源：[2026-09-12 审查报告](D:/A/MyProject/ai/Aifirtst/docs/superpowers/reports/2026-09-12-project-review.md)。报告中的缺陷尚未因本文档而得到代码修复。

## 1. 已确认的产品决定

- 来源仅为相机内存卡；继续接受来源卷永久拒写、来源与图库不同卷。
- 图库位于本机机械硬盘，约几千张照片、JPG/RAF 合计约 500GB，主要痛点是查重而非复制。
- 保留精确预检：确认前知道检测范围内哪些文件重复、哪些新增、各自路径和新增容量；用户查看结果后确认，仅执行该版本的计划。此决定取代此前接受轻量预检的选择。
- 预检阶段不创建照片、partial 或照片暂存文件；允许保存任务元数据、计划和证明记录。无法判定的文件单独列出，用户需解决或明确排除后才能确认所选集合。
- 先按文件名称和文件大小定位候选；名称与大小相同仅表示疑似重复，完全逐字节一致才能跳过或进入重复清理。
- 普通 D 标记默认按逻辑照片整组处理 JPG＋RAF。
- 用户已明确：重复清理可以显式只选择已证实重复的 JPG，保留 RAF；不得自动把未选择或没有保留副本证明的格式加入删除。

## 2. 核心变化与保持的效果

产品顺序固定为精确预检、查看结果、确认导入。名称大小预筛只是预检的第一阶段，不能把疑似结果当作已完成预检；不得后台默认确认、提前复制照片或执行中静默改变新增/跳过分类。

先用完整的候选索引排除不可能重复的文件，再对疑似重复做逐字节比较。不要求先给整个图库或整张卡建立完整哈希。没有候选的新增文件，预检仅读取必要元数据，不完整读取正文。

SHA-256 在必要的正文读取中同步计算，不单独开一轮整文件读取；完整相等仍须字节证明。第一处不同即可结束该候选比较，部分摘要不得保存为完整哈希。

预检缓冲可有界保留，但不能保证一直保留整批数据等用户确认。确认后必须校验计划和证据有效性：同一受控稳定观察可以复用；连续性无法证明时只复核有关文件，不重跑全卡预检。长度、mtime、路径相同不足以单独证明内容未变。

保持来源只读、不覆盖目标、写后验证和可解释恢复。优化取消不必要的读取，不能取消授权边界或承诺所有文件总共只读一次。

## 3. 候选范围与索引

### 3.1 先查询便宜的信息

候选查询使用当前 Library、媒体类型、文件名和精确字节长度，拍摄日期用于规划及候选排序，不仅凭近似元数据判断重复。

历史重复页保持已确认的精确完整文件名语义：区分大小写，目录不参与匹配；页面明确称为“同名重复检测”。改名副本属于未覆盖范围，未来若加入完整内容模式需单独命名和验收。

导入沿用已有大小写折叠规则，并保留已记录的来源→目标关系及合法数字后缀候选，避免应用曾把 DSCF0001.JPG 保存为 DSCF0001_2.JPG 后再次导入同一文件。历史映射只能定位候选，跳过仍需当前字节证明。不能将 _2 后缀映射任意扩大成模糊名称匹配。

### 3.2 目录只建立一次索引

本次来源树只轻量枚举一次。当前图库的名称/大小候选索引必须有明确扫描覆盖状态；必要时先做一次元数据刷新，不能把未扫描完整的索引解释为确定不存在候选。

每个目标日期目录在一轮规划内只枚举一次，维护本批已预留路径。预检必须同时检查本批来源之间的同名同大小候选，不能等导入一半才发现批内重复。批内相同文件选一个计划新增代表，其他项显示为依赖该代表成功导入后跳过；代表被取消、排除或失败时，依赖项等待或生成新计划，不能静默换代表写入。

新发布文件更新本批索引并履行已确认的依赖；计划变更只刷新受影响目录和步骤。批内比较需要读来源卡上的双方，应与查询历史图库的读量分开计量。

执行前复核当前文件与候选快照，目录/Root 变化按版本失效。应用外文件变化不能被路径字符串掩盖；结果表示本次受控观察的范围，不声称无成本获得整个图库的瞬时全局快照。

### 3.3 哈希索引为可选加速

完整哈希记录绑定 Asset、版本、RootBinding、长度、身份观察与算法版本。没有指纹的候选可直接比较，无需先额外完整哈希；有效指纹可以帮助候选排序或复用当前稳定观察。

旧哈希和相同名称/大小都不能独立授权跳过或删除。没有可靠连续性证据的历史哈希差异，也不能代替当前候选验证；发生已观察变化时使旧指纹失效。

## 4. 内存预算与并行方式

当前机器此前观测到约 31.91GiB 物理内存、当时空闲约 10.96GiB，空闲量不是长期保证。建议照片处理缓冲池硬上限为 512MiB，包含来源原文、预读队列、保留缓冲及 I/O 工作缓冲；例如先在预算内预留 8MiB 工作空间。按需分配，不提前固定占用 512MiB，不以填满内存为目标。

- 可以同时缓存多张照片，以实际分配容量计费，而非固定文件数量；申请和排队前预留字节预算，释放后归还。禁止多个任务分别认为自己都有 512MiB。
- 缓冲位于 Rust 后端，不克隆整份原文，不向 React 发送 Base64，不为内容比较解码像素。
- 预检期间，只预读需要内容比较的来源。来源卡顺序预读可与图库盘比较重叠，但机械硬盘默认只有一个大文件工作流；卡内批次比较也服从来源设备调度。
- 确认后的导入阶段，可以预读下一张已批准新增文件，与当前文件写入/验证重叠。队列满则暂停预读，取消时停止生产并安全释放。
- 等待用户确认时停止预读。仅可在预算内保留有复用价值的新增文件缓冲，受内存压力可淘汰；重复文件的原文通常释放。不能无限持有卡或全图库句柄来省读取。
- JPG/RAF 的逻辑组独立于缓冲和并发管理；可以分别处理，不能因共享名称错误合组。
- 单文件超过可用池预算或分配失败时，先等待/释放可淘汰缓冲，仍无法容纳则走有界流式路径；不静默扩容。
- 50GB/100GB 批量只增加处理轮数，不增加此上限。界面、数据库和预览另有开销，F06 无界预览缓存仍需单独修复。

多文件缓冲减少设备之间的等待，不减少必需内容读量；机械硬盘饱和后增加并发不保证更快。

## 5. 导入步骤与确认边界

### A. 枚举和候选预筛

验证来源/目标 Root 和卷边界，冻结本轮来源清单；读取必要身份、长度、日期和配对元数据。建立扫描覆盖明确的候选索引，用名称、大小、已知映射及合法后缀缩小范围，并纳入批内候选。

没有候选的文件直接形成计划新增项；这仅表示在明确检测范围内无重复，不代表全内容跨任意文件名查重。按日期索引和整批预留确定目标路径。元数据解析可能读取部分正文，不算完整正文遍数。

### B. 精确预检，只比较疑似重复

取得缓冲预算，打开受控来源句柄，验证身份，读入来源原文并同步计算哈希。按稳定顺序打开候选，逐块与来源内存比较：

- 全部相同且双方身份/路径校验通过：保存精确重复结果、保留副本、证明及其有效性条件。
- 第一处不同：排除该候选；所有有效候选均不同才列为新增，部分哈希不写入完整指纹索引。
- 不可读、失踪、身份变化或索引不完整：列为待处理或重试，不当成确定新增/重复。
- 多候选、本批多个内容类别必须全部正确划分，不仅与第一个比较就排除其他相等关系。

证明保存后原文可释放或有限保留。此时是预检判断，不是导入完成或最终跳过事实。超预算文件采用双端分块比较，必要补读单独计量。

### C. 查看结果与确认

预检完成后显示逐文件新增/重复列表、目标路径、相同保留副本、批内依赖、文件数、逻辑照片数及新增字节量。所选集合必须有确定结论；用户可排除待处理项，但不能把它们隐含当作新增。

空间检查基于已确认新增量，加上实现所需的临时/数据库余量；再次检查当前可用空间，不能保证其他程序不会占用。保留副本是本批新增代表时，代表只计一次。

Rust 保存不可变 planId/version/digest，前端查看和提交同一对象。修改选择导致依赖、路径或分类变化时生成新版本供查看。确认之前不得创建照片或 partial，也不得为了保存缓冲把整批照片落盘暂存。

### D. 确认后的计划与证据复核

复核选定来源、Library/RootBinding、目标路径、候选集合版本及相关证据，按文件在使用前再次检查，不把按钮点击时的一次检查当成整个执行期间的保证。

- 同一稳定观察持续有效：允许复用预检证明或原文。持有普通句柄本身不等于阻止修改，复用需要受控句柄的保护语义或经验证的可靠变化跟踪，同时有路径、目录及版本校验。
- 已释放相关保护、重新启动、拔卡重连、弱身份或无法证明连续性：对有关重复关系重新做一次流式字节比较并同步计算必要摘要；不得仅靠 size/mtime 或历史哈希跳过。默认不能假设跨人工确认的连续性可用。
- 复核仍与已确认计划相同：继续原计划，不重复弹窗。
- 新增/重复分类、来源内容、目标路径、保留副本或批内依赖发生实质变化：暂停相关步骤，展示更新的精确计划并重新确认；不得将预检重复项自动改成新增写入。
- 新增文件无预检完整内容摘要时，确认对象是可验证的所选文件身份及计划，不声称冻结了用户未读取过的每个字节。身份连续性不能可靠确认时，重新建立相关文件观察和计划确认；不能按同名路径冒认替换的卡或文件。

目标目录候选变化会触发受影响项目重新预检，不要求无条件重读全卡。缓存命中也必须验证来源与缓存的关联仍有效；陈旧缓存不能作为新来源原文。

对批内重复项，只有代表实际发布且验证成功后才能记录跳过，并将预检来源间证明与代表写入证明连接起来。证据链无法可靠连续复用时，读取实际保留副本复核；代表失败不连带产生虚假跳过。

### E. 仅执行已确认新增文件，写后验证

从有效保留缓冲复用原文，或按需从当前来源读取到预算内缓冲，并同步计算哈希。如果预检已形成完整来源摘要，在本轮读取中核对它；差异触发计划更新。与有效证据配合判断，不能把哈希单独作为删除或跳过授权。

只有当前步骤准备创建文件时，持久化创建意图；使用唯一应用自有 partial 和 create-new 语义。预检路径预留不等于文件 ownership，不能提前为全部排队项建立疑似已创建文件事实。

从缓冲写入 partial 一次，完成刷新，再回读一次与原文逐字节比较并同步计算摘要。校验根目录和冲突后不覆盖发布，提交实际结果、索引和步骤终态，再释放当前缓冲及保护。

超预算新文件退化为复制时来源读一次、写后来源和目标流式比较一次，即仅执行阶段来源约两遍、目标一遍；预检比较读量另计。提交失败或结果不确定保留恢复证据，不宣称成功。

### F. 读取预算与限制

以下是单文件可入缓冲、无额外候选/重试的逻辑正文读量；每个候选探测、元数据和批内比较另计。

| 场景 | 预检 | 确认后 | 整体典型读量 |
| --- | --- | --- | --- |
| 无候选新增 | 不完整读正文 | 来源 1 遍，新增目标验证 1 遍 | 来源 1，目标 1 |
| 有候选但不同，缓冲已淘汰 | 来源 1 遍，候选读至差异处 | 来源再读 1 遍，新增目标验证 1 遍 | 来源 2，目标验证 1，另加候选探测 |
| 有候选但不同，有效缓冲保留 | 来源 1 遍，候选读至差异处 | 复用原文，新增目标验证 1 遍 | 来源 1，目标验证 1，另加候选探测 |
| 重复，预检证明连续有效 | 来源及命中候选各 1 遍 | 校验有效性后记录跳过 | 双方各 1 遍，仅在连续性已证明时 |
| 重复，需要跨确认重新证明 | 来源及命中候选各 1 遍 | 双方各再读 1 遍并合并证明步骤 | 双方各 2 遍；不能再分成多轮哈希和比较 |

全部为无候选新增且可入缓冲时，50GB 导入约读来源 50GB、读目标 50GB、写目标 50GB；100GB 对应约各 100GB。这不是任何批次都成立的承诺。不得继续引用 V2“所有典型重复都只读 1＋1”作为 V3 无条件指标，也不把逻辑读量比例换算成耗时保证。

## 6. 历史同名查重

1. 使用完整文件名、类型和大小分组；单成员组不读取正文。
2. 把一个代表文件读入有界内存一次，计算哈希并冻结其身份。
3. 其他候选顺序读取，与代表原文比较并同步建立证明；完全一致的成员无需另开一轮完整哈希。
4. 一个桶含不同内容类别时，必须正确划分类别，不能只与第一份比较后把其余都排除。可在不同后继续本轮顺序读取完成哈希以分组，未建立字节证明的其他同哈希类别再安排比较；这些额外读取明确计量。
5. 已读取数据对应的相等事实在稳定句柄约束内及时提交。最终结果版本核对失败则过期/取消，不通过再次全组哈希掩盖版本冲突。
6. 用户真正加入待删除及执行回收时，仍建立各自操作时点的新证明；展示结果不能成为永久删除授权。

单一同内容组、代表文件装得进预算且没有重试时，n 份 S 大小文件可以读 nS。多个类别、预算不足、句柄数量上限或代表淘汰可能补读；不承诺任意输入均只读一次。批次仅保留有界数量句柄，不能为了少读无限持有全图库文件。

结果显示、加入待删除、批量加入和回收协调必须共用同一个有效版本解析器：统一处理原始 run revision、Applied 协调链、RootBinding 和当前 catalog revision。清掉一份后，剩余集合可在合法协调后继续使用。

## 7. 必须配套的任务和 UI 设计

### 7.1 任务状态与恢复出口

| 状态 | 用户可执行动作 | 约束 |
| --- | --- | --- |
| 预检中 | 查看筛选/比较进度、取消 | 不创建照片文件；尚未完成精确判断不能确认 |
| 预检完成/待确认 | 查看结果、修改选择、确认、取消 | 所选集合结论确定；修改或失效生成新版本 |
| 读取/比较/复制/验证 | 查看进度、取消剩余、离开页面后返回 | 使用同一任务取消信号；系统动作收尾后持久化结果 |
| 等待原卡 | 选择来源进行只读核验、取消剩余 | 核验入口不等于普通配置换源，不直接改旧绑定 |
| 等待空间 | 检查后继续、取消剩余 | 已完成文件不回滚，不自动扩展目标 |
| 计划变化 | 查看并确认新版本、取消剩余 | 已完成事实不可改写 |
| 需要处理 | 查看具体步骤、受控重试或取消剩余 | 不自动认领/删除身份不明的 partial |
| 完成/已取消 | 看报告、返回图库、开始新任务 | 已提交终态，正确释放任务占用 |

原卡重选：先只读验证是否符合当前任务来源。身份足够可靠时恢复；弱身份来源不能仅靠路径认作原卡。可用冻结内容证据验证相关文件；尚未开始且身份无法可靠证明的剩余项，需要新的明确确认，无法证明时也必须允许结束原任务。不得在未完成任务存在时把这个核验入口一律封死。

排队但未开始的步骤没有文件系统动作，恢复时保留为可执行队列。只有实际进入创建意图而动作结果不确定的当前步骤，才进入针对该步骤的 NeedsAttention。

取消/关闭时停止调度新步骤，等待当前系统动作或回调结束，先提交物理事实和终态，再释放 lease/reservation。身份不明产物保留并单独记录/隔离，不能为了取消成功删除它们，也不能无条件释放仍有工作线程使用的占用。

### 7.2 应用级任务状态

任务状态由 Rust 持久层和协调器提供，React 页面挂载时读取当前真实状态；离开页面不丢失进度、取消入口或计划版本。导入/扫描完成通过 catalog revision 通知刷新图库、待删除摘要及报告。

进度包含当前阶段、文件、已读字节、已处理文件数、等待原因。尚不确定的候选总读量标为估计，不把完成哈希显示成全部验证完成。等待 I/O 被取消应持久化为 Cancelled，而不是 Failed。

### 7.3 调度与扫描

按物理设备统一调度导入、历史查重、回收前复证、后台扫描及缓存预取，消除绕过调度器的大读。图库盘默认只运行一个大文件工作流，小量浏览请求在有界块边界获得响应机会，不增加无界队列。

增量扫描先比较身份和解析器版本，未变化元数据可复用；已观察变化、解析失败待修复或版本不适配时才重新解析。目录索引完整性和文件变化必须在数据库版本中反映，不能靠仅更换“增量”名称达到优化。

## 8. 删除范围与配对规则

用户已明确：普通 D 默认整组；重复清理允许明确只选已证实重复的 JPG 并保留 RAF。确认框逐文件列明删除/保留路径和格式，未选择的 RAF 不得因 JPG 的证明被附带删除。

UI 列表、确认、执行、重试与结果协调均限定同一当前 Library + RootBinding；任务运行期间固定其范围。最终执行使用冻结的具体资产集合及版本，不能仅靠文件数/总大小相同代替集合身份。

配对与重复是不同关系。导入组 ID 由任务、来源目录和配对证据等稳定信息建立，展示文件名不作主键；不同目录同名文件不误合组。历史配对先按可靠拍摄时间及相机信息过滤，再检查候选唯一性，避免不同年份同名导致既有配对拆散。

重复清理每个删除成员都需要当前相同保留副本，保留副本不能同时处于本次待删除集合。部分回收成功按逐文件事实报告，不能承诺 JPG/RAF 两个物理文件原子删除。

## 9. 审查报告逐项核对

分类说明：A=核心流程直接针对；B=必须实现的配套改动；C=独立修复包，单改导入/查重仍会存在；D=明确的产品边界。所有分类都是设计覆盖程度，不表示当前代码已修复。

| 报告项 | 分类 | 本版如何处理；还会不会存在 |
| --- | --- | --- |
| F01 导入反复完整证明 | A | 保留精确预检，只比较候选；哈希与字节比较合并，执行复核按有效性限定范围。跨确认连续性不足仍需一次重证，不保证所有文件只读一次。 |
| F02 历史查重反复读 | A | 代表内存复用、比较时哈希，取消固定的多轮重读；复杂类别有额外读取但必须有界。 |
| F03 日期目录反复枚举 | A | 每轮每目录一次索引＋全批路径预留；变更只刷新受影响目录。 |
| F04 调度遗漏/伪增量 | B | 所有重读进入统一设备调度，扫描按身份与解析版本复用；只换比较算法仍会存在。 |
| F05 进度/取消不完整 | B | 应用级阶段和字节进度＋统一取消信号；每个读取循环和排队入口均覆盖。 |
| F06 完整 JPEG 预览及无界缓存 | C | 导入缓冲上限不能修复它。需要另接真正缩略图、磁盘缓存和按字节限制的预览 LRU。 |
| L01 回收混入其他图库 | B | 统一列表/确认/执行/重试的 Library、Binding、冻结集合范围；性能重构本身无效。 |
| L02 显示新计划却提交旧摘要 | B | 共享权威 planId/version/digest，异步更新同时更新显示与提交依据。 |
| L03 原卡恢复重选死路 | B | 增加任务内原来源只读核验入口；弱身份证据不足走新确认或取消，禁止按路径冒认。 |
| L04 未开始步骤也阻断恢复 | B | 队列与实际创建意图区分；ownership 仅在当前步骤创建阶段建立，恢复仅处理真实动作。 |
| L05 等待状态无法取消 | B | 所有非终态有退出路径；取消事务和句柄收尾后释放正确占用，未知产物单独保留。 |
| L06 跨目录同名无法导入 | B | 稳定组 ID 与展示名分离，整批目标路径统一预留，本批新资产也进入候选索引。 |
| L07 协调后结果不能继续使用 | B | 所有入口使用统一有效版本解析器，不再有显示读新版本而提交检查旧版本的分叉。 |
| L08 页面重进/完成后旧列表 | B | 应用级真实任务状态＋catalog revision 刷新，离开页面不丢活动任务。 |
| L09 无效日备份被当成功 | C | 仍需独立修复：验证已有备份，新备份先临时写入、完整验证后发布；exists 不代表成功。 |
| L10 取消扫描变 Failed | B | 调度等待、文件循环、扫描收尾统一取消语义并持久化，不能只修按钮。 |
| R01 安全规则固化为多次读取 | A | 以证明结果与读取预算验收，允许一次稳定读取完成多项证据，执行前边界继续保留。 |
| R02 全库同名干扰历史配对 | C | 属于独立 PairingService 修复，按时间/相机证据后检查唯一性；名称大小预筛不会自动修好。 |
| R03 同名检测被误解为全内容 | D | 明确叫同名重复检测；改名副本范围不覆盖。导入保留已知映射和后缀候选，避免应用重命名回归。 |
| R04 整组删除与单格式重复清理 | D | 用户已明确允许显式只清理重复 JPG；普通 D 默认整组，确认及后台资产集合分别约束。 |
| R05 恢复/取消/性能验收不完整 | B | 每状态都有可达操作，真实后端端到端验收和读量计数替代仅正则/演示后端测试。 |

因此：只实现“名称大小预筛＋内存”不能解决整份报告。完整实现本版 A/B 项后，相关问题才具备消除条件；F06、L09、R02 仍需独立修复验收，D 项是明确保留的范围。

## 10. 新设计特别需要防止的回归

- 缓冲无界、预读绕过预算、整份原文被复制或 Base64 传到前端。
- 名称和大小相同直接跳过、相同哈希直接删除、提前停止后的部分哈希被标成完整。
- 候选不完整/不可读被当成确定不重复；新发布文件未加入本批索引导致批内重复复制。
- 用户停留在确认框时计划变更，旧授权被静默用于新来源/新路径。
- 来源缓冲或候选保护释放后仍把旧观察当成当前有效授权；把普通句柄、mtime 或相同长度误当成内容连续性证明。
- 预检尚未完成就允许确认，等待确认时偷偷写 partial，或执行时静默改变预检新增/跳过分类。
- 只检测图库副本漏掉批内重复，代表被排除/失败后依赖项仍记录成功跳过。
- 为了少读把所有历史候选永久锁在句柄表中，或漏掉一个桶内第二个相同内容类别。
- 崩溃后凭 partial 路径认领文件、取消时删除未知产物、提前释放仍被 worker 使用的租约。

## 11. 实施与验收

先补配套任务/范围基础，再启用新内容读取路径；独立缓存/备份/配对修复分别验收。迁移应新增计划/证明版本而非改写历史不可变事实，旧未完成任务需要明确兼容恢复或受控取消，不能直接套用新状态含义。

至少覆盖：

1. 同名同大小但第一块不同：不跳过；候选可提前结束，不能记录部分完整哈希。同名完全相同：必须完整逐字节验证。
2. 文件名不同、大小不同、大小写边界、合法 _2 后缀、历史映射、同批两个来源目录同名文件的正确候选与路径规划。
3. 无候选新增正文读取 S＋S；疑似但不同且缓冲淘汰时来源 2S；重复无连续性时双方各 2S。只有连续性有证据的分支验收双方各 S；统计额外候选及批内比较。
   多文件预读按实际容量和工作缓冲总计不超过 512MiB，50/100GB 不随总量增长；等待确认停止预读且不创建照片/partial，超预算与分配失败正确退化。
4. 哈希碰撞注入、来源/目标变化、Root 替换、目标冲突及候选不可读：不产生错误跳过、覆盖或删除。
5. 原卡重连、等待空间、所有取消时点、创建/验证/发布与提交之间的崩溃：可解释恢复且未开始步骤不被误锁。
6. 导入期间离页重进、计划异步更新后重确认、导入/扫描完成刷新，使用实际异步命令行为验证。预检后长时间等待、同大小同 mtime 内容替换、缓存淘汰、重启、保留副本删除及批内代表失败：失效结果不被默默执行，受影响项目重新预检，分类/路径变化需要重确认。
7. A/B 图库回收隔离、三份重复清一份后继续清、只选重复 JPG 而独有 RAF 保留、跨年同名配对回归。
8. 无效日备份拒绝、真实缩略图与内存 LRU 生效，作为独立修复包的准入项。
9. 分别计量来源/目标实际 Read 返回的字节数、目录枚举次数、内存峰值、队列等待和阶段耗时；物理盘冷/热缓存表现单独测量，不把逻辑读量换算成承诺时间。

本次仅更新设计及对照文档，未运行照片导入/回收，也未修改业务代码。实现后的正确性、恢复和性能仍需重新验证。
