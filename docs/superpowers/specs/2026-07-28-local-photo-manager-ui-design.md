# 本地 Fuji 照片管理器 v1 核心照片视图 UI 设计

- 状态：视觉与书面规格已最终确认，待按阶段实施
- 日期：2026-07-28
- 最终确认：2026-07-29
- 适用平台：Windows 10/11 x64 桌面
- 上位规格：`2026-07-28-local-photo-manager-design.md`
- 相关 UI 规格：`2026-07-29-local-photo-manager-import-location-ui-design.md`、`2026-07-29-local-photo-manager-operations-ui-design.md`
- 覆盖范围：图库视图、待删除视图及其关键状态

## 1. 设计结论

v1 核心照片视图采用用户确认的 **白色沉浸式画布**：

1. 界面整体为白色和浅灰色，不使用暗色摄影工作台主题。
2. 左右栏保持窄而稳定，中间照片画布占据绝大多数空间。
3. 右栏上部只承载当前照片信息和参数。
4. 右栏操作按钮固定在最下方，与上方参数之间保留明显的弹性留白。
5. 图库页保留 Photoshop、文件位置和待删除按钮。
6. 待删除页只用于复核和删除，不显示 Photoshop 或文件位置按钮。
7. 危险红色只用于待删除状态、删除计数和删除动作，不用于普通导航。
8. “待删除”是按状态出现的条件视图：没有任何待处理删除项时，顶栏页签和底栏计数都不显示；首次成功标记后只显示入口，不打断图库中的连续筛选。

产品仍是个人相册管理器，不通过复杂面板、评级控件或专业选片术语营造专业筛片软件的感觉。

## 2. 信息架构

v1 最多出现两个照片视图：

- **图库**：始终存在，也是每次普通启动的默认照片视图；用于浏览全部当前存在的 Photo、标记或取消待删除，以及使用外部工具。
- **待删除**：条件视图；逐张复核已有标记和删除问题，取消标记，确认并执行整批 Windows 回收站操作。只有存在至少一个待处理删除项时才显示入口并允许进入。

本规格使用 `pendingReviewCount` 表示 Rust 权威 `PendingDeleteSummary.total_count`，即待删除视图中的去重 Photo 条目总数。它包括有效 `DeletionMark`，也包括因成员变化、文件缺失、部分删除或 `NeedsAttention` 而仍需用户处理的删除问题项；它不等同于本批次可执行删除的 Photo 数。可执行数量、问题数量和真实文件数量必须在待删除页分别显示。React 不通过本地乐观增减自行决定页签显隐。

导入、设置和操作报告使用同一视觉 token，详细布局由相关 UI 规格冻结。它们是临时工作流或工具页，不得改变“图库”和条件显示的“待删除”这两个照片视图的导航名称、数量或行为，也不得在顶栏增加常驻的第三个照片视图。共享顶栏提供一个带文字标签或可访问名称“设置”的非页签工具按钮；它与“图库 / 待删除”视图切换在结构和样式上分开，不能渲染成第三个照片页签。

## 3. 应用外壳与参考尺寸

### 3.1 参考布局

设计基准为 1440 × 900 的 Windows 桌面窗口。尺寸是实现参考，不要求逐像素写死：

| 区域 | 参考尺寸 | 调整行为 |
|---|---:|---|
| 顶栏 | 52 px 高 | 固定高度 |
| 底部状态栏 | 30 px 高 | 固定高度 |
| 左侧 Filmstrip | 96–112 px 宽 | 窄栏，窗口缩放时保持范围 |
| 右侧详情栏 | 260–286 px 宽 | 保证元数据与按钮完整可读 |
| 中央画布 | 剩余空间 | 吸收全部宽高变化 |

建议窗口最小尺寸为 1100 × 700。低于该尺寸不继续压缩照片或按钮，而是由桌面窗口设置阻止继续缩小。

### 3.2 结构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 品牌     图库 [待删除 N]      日期上下文   排序   导入照片  设置 │
├──────────┬──────────────────────────────────────┬───────────────────┤
│          │                                      │ 文件与格式        │
│ 纵向     │                                      │ 拍摄时间          │
│ Filmstrip│              当前照片                │ 照片参数          │
│          │                                      │                   │
│          │                                      │     弹性留白      │
│          │                                      │                   │
│          │                                      │ 底部操作区        │
├──────────┴──────────────────────────────────────┴───────────────────┤
│ 当前位置 / 总数               快捷键提示            [待删除 N]  │
└──────────────────────────────────────────────────────────────────────┘
```

方括号中的“待删除”页签和底栏数量只在 `pendingReviewCount > 0` 时渲染；为 0 时不保留禁用项、`待删除 0` 文案或空白占位。

右栏使用纵向 Flex 布局：信息区在顶部，操作区在底部，中间 spacer 使用 `flex: 1`。窗口高度下降时先压缩留白；达到最小留白后，只有上方信息区允许滚动，底部操作按钮保持可见。

## 4. 视觉语言

### 4.1 色彩

| Token | 初始值 | 用途 |
|---|---|---|
| `surface` | `#FFFFFF` | 顶栏、Filmstrip、详情栏、状态栏 |
| `canvas` | `#F1F2F4` | 照片周围的中央画布 |
| `text-primary` | `#202633` | 主要文字 |
| `text-secondary` | `#7A8390` | 次要说明、标签 |
| `border` | `#E4E7EC` | 栏分隔线和普通边框 |
| `selection` | `#3D6DD8` | 图库当前照片描边、普通焦点 |
| `danger` | `#BD3B4C` | 待删除徽标、数量和删除动作 |
| `primary-action` | `#282F3A` | Photoshop、导入等主要非危险按钮 |

浅灰画布用于区分白色工具区与照片边缘。不得把中央画布改为纯白，以免浅色照片失去边界。

### 4.2 字体与密度

- 首选 `Segoe UI`，中文回退到 `Microsoft YaHei` 和系统无衬线字体。
- 正文使用 12–14 px；元数据标签使用 10–11 px；文件名使用 15–16 px 半粗体。
- 基础间距单位为 4 px，常用间距为 8、12、16 和 20 px。
- 普通控件圆角 8 px；应用预览外壳可使用 14–16 px，但产品窗口本身不模拟悬浮卡片。
- 阴影只用于当前照片与浮层，不为每个面板增加卡片阴影。

### 4.3 状态不能只依赖颜色

- 待删除缩略图同时显示红色圆形 `D` 徽标。
- JPG/RAF 使用文字与 `✓/×`，不能只使用绿色或灰色。
- 离线、不支持删除和需要重新确认必须有明确文本。
- 键盘焦点使用清晰描边，不用仅改变背景色表示。

## 5. 图库视图

### 5.1 顶栏

从左到右显示：

1. 简洁的 Fuji Library 标识。
2. 始终显示“图库”；`pendingReviewCount > 0` 时在其后显示“待删除 N”，当前视图使用浅灰选中底色。
3. 当前日期上下文，例如 `2026 / 07 / 27`。
4. 排序选择，例如“最新优先”。
5. 深色主按钮“导入照片”。
6. 非页签工具按钮“设置”；使用齿轮图标时仍必须提供可见提示和可访问名称。

顶栏不显示搜索框、评分或专业筛片状态。“待删除”不以禁用页签、零计数或占位形式常驻：

- 没有待处理删除项时只显示“图库”，应用默认停留在图库。
- 在图库中通过 `D` 或右栏按钮首次成功添加标记后，先以 Rust 事务成功结果更新摘要，再显示“待删除 1”；当前视图仍是图库，并按既有规则前进到下一张，不自动打开待删除页。
- `R` 恢复标记、启动时恢复持久标记或出现删除问题项，只要使 `pendingReviewCount > 0`，同样显示页签。
- 页签上的 `N` 是待复核条目总数；存在问题项时同时显示非纯颜色的警告标识，不能把问题项误计为可执行删除项。

本文对首次标记后的行为统一表述为“前进到下一张，但不自动切换到待删除视图”。不得使用“不会自动跳页”这种可能同时指照片前进和路由切换的含糊文案。

“设置”按钮通过 `Enter` 或 `Space` 打开设置工具页。打开时保存来源照片视图、排序与当前 `PhotoId`；从设置返回时优先恢复该视图和 Photo，并把键盘焦点交还“设置”按钮。若来源是已经失效的待删除路由或 Photo 已不存在，则按既有路由保护和最近下一张规则回到图库。直接打开设置路由时，“返回图库”进入图库当前游标；首次尚未绑定 Root 时，设置中的照片文件夹页作为启动门，不能绕回虚假的空图库。

### 5.2 Filmstrip

- 单列纵向虚拟列表，缩略图使用统一比例和 6–8 px 间距。
- 当前 Photo 使用蓝色双像素描边。
- 待删除 Photo 右上角显示红色 `D` 徽标。
- 滚动时当前项保持可见；鼠标位于 Filmstrip 时滚轮切换 Photo。
- 首尾不循环。

### 5.3 中央照片画布

- 使用浅灰背景和居中的适应窗口预览。
- 照片保持宽高比，不裁切、不拉伸。
- v1 不显示缩放滑杆、直方图、对焦点或比较视图。
- 加载时保留稳定画布尺寸并显示轻量进度反馈，避免布局跳动。
- RAF 内嵌预览失败时使用明确占位状态，不用损坏图片图标冒充原图。

### 5.4 右栏信息区

从上到下显示：

1. 文件名。
2. `JPG ✓/×` 与 `RAF ✓/×` 格式徽标。
3. 拍摄日期和相机本地时间说明。
4. 相机、镜头、光圈、快门、ISO、焦距、尺寸和容量。

当拍摄时间未知时，右栏必须明确显示“拍摄时间未知”，并另行显示文件时间供参考；文件时间不得标注或解释为拍摄时间，也不得参与时间线升序、降序或日期分组，日期未知项始终位于时间线末尾。

图库页不在按钮旁或默认信息区显示绝对文件路径。

### 5.5 右栏底部操作区

按钮固定在详情栏底部，顺序为：

1. **用 Photoshop 打开 RAF**：深色主按钮；JPG-only 时禁用并说明没有 RAF。
2. **打开当前文件位置**：白色描边按钮。
3. **标记待删除 / 取消待删除**：红色描边按钮，并显示快捷键 `D`。

按钮区顶部使用细分隔线。信息较少时仍保留整块留白，不把按钮向上贴近参数。

### 5.6 底部状态栏

- 左侧：当前位置和总数，例如 `2,486 / 98,214`。
- 中间：克制显示 `←/→` 浏览和 `R` 撤销提示。
- 右侧：仅在 `pendingReviewCount > 0` 时以红色文字显示“待删除 N”；存在问题项时追加“问题 M”文字或警告图标及可访问标签。

`pendingReviewCount = 0` 时右侧摘要整体不渲染，也不显示“待删除 0”或为它预留固定空位。

存在未终结的扫描、Import、Recycle 或恢复协调时，底部状态栏增加持续可见的活动任务摘要，使用“正在扫描照片”“正在导入照片”“正在移入 Windows 回收站”或“等待处理”等用户文案，并提供“返回进行中任务”。摘要可以显示开始时间、已完成/总数和当前阶段，但不得显示 Job、Attempt、Step、RootId 或文件身份等内部 ID。任务到达终态后状态条消失，结果入口按报告规格呈现。

## 6. 待删除视图

待删除视图只在 `pendingReviewCount > 0` 时存在于可见导航和可访问路由中。用户必须主动点击已经出现的“待删除 N”页签进入；首次标记、会话撤销、后台协调和普通重启都不得自动把正在浏览图库的用户切到该页。直接打开已失效的待删除路由且计数为 0 时，应用立即替换为图库路由，不渲染待删除空页。

### 6.1 设计目标

该页只承担四个任务：

1. 查看当前待删除 Photo 及其物理文件组成。
2. 取消不应删除的标记。
3. 对全部剩余有效标记发起整批删除确认。
4. 对部分失败或结果不明的剩余项执行规格允许的重试、重新扫描或取消剩余意图。

不得把该页变成第二个通用图库或文件工具页。

### 6.2 与图库页保持一致的部分

- 使用相同应用外壳、白色主题和三栏比例。
- 中央仍以当前照片为主。
- 右栏仍为“顶部信息 + 弹性留白 + 底部动作”。
- Filmstrip 仍为纵向虚拟列表。

### 6.3 Filmstrip 与当前项

- Filmstrip 只显示当前待删除清单中的 Photo。
- 每个缩略图都显示 `D` 徽标。
- 当前项使用危险红色描边，明确表示正在复核待删除项。
- 中央画布左上方显示“待删除 · 第 N / M 张”。
- 不显示复选框，因为执行删除处理确认时的全部剩余有效项目。

### 6.4 右栏信息区

从上到下显示：

1. “待删除 · 已持久化”或当前异常状态。
2. 文件名和 JPG/RAF 组成。
3. 相对 Fuji Root 的目录；不默认显示绝对路径。
4. 拍摄时间、物理文件数、合计容量、尺寸、相机和镜头。

### 6.5 待删除页禁止的按钮

待删除页明确不提供：

- “用 Photoshop 打开 RAF”
- “打开当前文件位置”

这两个按钮只存在于图库页。

### 6.6 右栏底部操作区

右栏底部只包含：

1. **取消当前待删除**：中性浅灰按钮，显示快捷键 `D`。
2. **批次摘要**：显示剩余 Photo 数、真实文件数和总容量，并说明下一步仍有最终确认。
3. **执行删除…**：红色实心按钮；省略号表示不会立即进行物理操作。

批次摘要和执行按钮属于一个固定底部区域，与上方参数之间保持明显留白。

当前项为删除问题时，底部动作替换为与问题相符的处理入口：

下表中的反引号状态名只用于规格和实现映射；普通界面显示同一行的中文问题与动作，不显示内部状态码。

| 用户可见问题 | 可用动作 | 明确禁止或后续行为 |
|---|---|---|
| 标记已失效：配对成员或文件在标记后发生变化 | “取消失效标记”；可另行“重新扫描”更新当前事实 | 重新扫描不能刷新旧标记快照。取消后按既有清单选择规则留在下一问题项或在清零时回到图库；用户只有返回图库检查当前文件后才能重新按 `D` |
| 文件缺失或照片文件夹离线 | “取消失效标记”；照片文件夹可重连时提供“前往照片文件夹设置” | 离线或文件仍缺失时不能重新标记或执行删除；重连/重扫也不会自动恢复旧标记 |
| 文件有多个目录入口或其他原因导致不支持安全删除 | “取消失效标记” | 在重新扫描证明能力恢复前，不提供重新标记或删除 |
| `RetryableFailed` 或 `Partial` | “重试剩余文件…”和“取消剩余删除” | 重试先打开新的剩余 Photo 数、文件数和容量确认，不直接执行 |
| `NeedsAttention` 或物理结果不明 | 先显示“重新扫描确认”，并在存在尚未执行意图时显示“取消剩余删除” | 只有重扫证明原身份文件仍在原位后才显示“重试剩余文件…”；绝不提供“标记为成功” |

“取消失效标记”只移除已经无效的删除决定；“取消剩余删除”只取消尚未成功的后续意图。两者都不能把已进入 Windows 回收站的文件改写为未删除或成功恢复。问题原因、建议动作和已成功/仍在原位/结果不明的真实文件数量必须以文字呈现，不能仅依赖颜色或内部状态名。

如果 Import 执行正在活动，用户仍可进入待删除页只读复核或取消标记，但“执行删除…”和全部删除重试入口禁用，旁边说明“照片正在导入；完成或取消剩余导入后可执行删除”，并提供“返回进行中任务”。Rust 的写入门仍是最终约束，不能只依赖按钮禁用。

### 6.7 最终确认对话框

点击“执行删除…”后才打开模态确认框：

- 标题明确写“移入 Windows 回收站”。
- 显示逻辑 Photo 数、物理文件数和总容量。
- 配对照片可展开查看 JPG 与 RAF。
- 说明应用内 `R` 将失效，执行后需通过 Windows 回收站恢复。
- 主按钮为“移入 Windows 回收站”，次按钮为“取消”。
- 不出现“永久删除”“仍然删除”或绕过回收站的选项。

对话框打开期间禁用全局 `D/R/←/→` 和滚轮切图。

### 6.8 清零、问题项与重启

- 在待删除页取消最后一个标记且事务成功后，以一次界面状态切换返回图库、定位到刚取消标记的 Photo，并隐藏顶栏页签和底栏计数；不得先渲染“没有待删除照片”的中间空页。
- 执行删除后，只有全部相关结果已经安全落库且 `pendingReviewCount` 确认归零，才返回图库并隐藏入口。图库定位到当前排序中最近的下一张；没有下一张时使用上一张，图库确实为空时才显示图库空状态。
- 如果删除只完成一部分、证据不完整，或存在成员变化、文件缺失、`Partial`、`NeedsAttention` 等问题，问题 Photo 继续占用一个待复核条目；页签和底栏摘要保持可见，页面明确区分“可执行删除”和“需要处理”，不得因为有效标记数为 0 就隐藏问题。
- `RetryableFailed` 或 `Partial` 只允许重试仍在原位且身份匹配的剩余文件，或取消剩余删除；每次重试都是新的不可变 Attempt，旧的成功、失败和不确定结果继续保留在报告中。
- `NeedsAttention` 必须先重新扫描。若能证明原身份文件仍在原位，才允许重试；无法证明时不猜测物理结果，只允许取消尚未执行的意图并引导用户检查 Windows 回收站。
- 没有可执行项但仍有问题项时，“执行删除…”禁用并解释原因；UI 不提供把不确定结果直接标记为成功的入口。只有 Rust 协调确认问题已解决或用户完成规格允许的取消/恢复操作后，条目才能从摘要移除。
- 从 Windows 回收站恢复出的文件经扫描后作为普通、未标记的照片返回图库，不自动恢复旧标记或加入旧 Attempt。
- 普通重启后始终默认进入图库。如果持久状态恢复出标记或问题项，首屏即显示“待删除 N”页签和底栏摘要，但不自动进入待删除页；如果没有任何条目，则两处保持隐藏。

## 7. 交互反馈与关键状态

| 状态 | 界面反馈 |
|---|---|
| 正在加载预览 | 保留当前布局，画布内显示轻量加载反馈 |
| `D/R` 写入 pending | 暂停导航和重复输入，当前按钮显示提交中 |
| 首次标记成功 | Rust 事务成功后一起更新徽标、`pendingReviewCount`、顶栏页签和底栏摘要，再在图库前进；不自动进入待删除页 |
| 取消或撤销成功 | Rust 事务成功后一起更新徽标、摘要和显隐；归零时按当前所在视图执行清零规则 |
| 标记失败 | 保持当前 Photo，显示可读错误，不前进 |
| Root 离线 | 顶部显示离线条；只允许会移除标记的动作 |
| 配对或文件身份变化 | 作为问题项保留在待删除页，显示“需要重新确认”，禁止对该项执行 |
| 失效标记待处理 | 按第 6.6 节显示“取消失效标记”及适用的重连/重扫入口；不得自动更新快照或迁移删除决定 |
| hard link 或不支持删除 | 明确显示“不支持删除”，不进入有效批次 |
| RAF 预览失败 | 中央显示 RAF 预览不可用占位；图库页仍可用 Photoshop |
| 删除部分失败或 `NeedsAttention` | 保留问题条目和错误报告，逐文件显示成功、失败或不确定，不显示整体成功，也不隐藏待删除入口 |
| 可安全重试的剩余文件 | 显示剩余文件数与容量；用户确认后创建新重试 Attempt，不改写旧结果 |
| 结果无法证明 | 先提供“重新扫描确认”，不提供直接标记成功；无法确认时提示检查 Windows 回收站 |
| 待处理项归零 | 在已提交的权威摘要归零后隐藏页签和底栏计数；若当前在待删除页则直接返回图库，不显示待删除空页 |
| 重启恢复出待处理项 | 默认进入图库，同时立即显示已恢复的页签和摘要，不自动切页 |
| Import 执行活动 | 保留浏览与复核；删除执行和删除重试禁用，显示活动任务摘要与“返回进行中任务” |
| Recycle 执行活动 | 暂停 `D/R`；共享状态栏显示进度与返回入口，导入执行由导入 UI 禁用 |

错误提示优先出现在受影响区域附近；Critical 或批次级错误使用持续可见的页面消息，而不是几秒后消失的 toast。

## 8. 组件边界

建议 React 组件边界：

```text
PhotoAppShell
├── TopBar
│   ├── LibraryViewTabs
│   │   ├── LibraryTab
│   │   └── ConditionalPendingDeleteTab
│   ├── ToolActions
│   │   └── SettingsButton
│   ├── DateContext
│   ├── SortControl
│   └── ImportButton
├── ActiveTaskRouteGuard
├── PendingDeleteRouteGuard
├── PhotoWorkspace
│   ├── VirtualFilmstrip
│   ├── PhotoCanvas
│   └── PhotoInspector
│       ├── PhotoIdentity
│       ├── PhotoMetadata
│       ├── FlexibleSpacer
│       ├── LibraryActions       图库页
│       ├── PendingDeleteActions 待删除页
│       └── DeleteProblemActions 删除问题项
├── StatusBar
│   ├── ConditionalPendingDeleteSummary
│   └── ActiveTaskStatus
└── RecycleConfirmationDialog
```

`PhotoInspector` 共享外壳和信息组件，但图库动作与待删除动作必须是两个明确组件，避免以后把 Photoshop 或文件位置误带入待删除页。

`LibraryViewTabs`、`PendingDeleteRouteGuard` 和 `ConditionalPendingDeleteSummary` 必须消费同一份 Rust 权威 `PendingDeleteSummary`，至少包含 `total_count`、`executable_count`、`problem_count` 和 `needs_attention_count`。显隐判断统一使用 `total_count > 0`；组件不得各自计算数量，也不得在命令成功返回前乐观显示、隐藏或跳转。`PendingDeleteRouteGuard` 负责在最后一个条目消失时原子完成图库路由和选中 Photo 的切换，避免短暂出现空白待删除页。

`SettingsButton` 是工具动作而不是 `LibraryViewTabs` 的成员。`ActiveTaskStatus` 和 `ActiveTaskRouteGuard` 消费同一份 Rust 权威活动任务摘要，负责返回正确的进行中页面以及禁用互斥写动作；前端不得根据本地路由自行推断任务已经结束。

UI 只提交 `PhotoId`、`photo_version`、`OperationId` 或 `DeletionBatchId`，不把展示路径当作文件操作授权。

## 9. 窗口缩放与可访问性

- 中央照片区优先获得新增空间，Filmstrip 和详情栏只在规定范围内变化。
- 高度不足时压缩弹性留白，再滚动参数区；底部动作始终可见。
- 所有按钮必须支持键盘焦点和清晰焦点环。
- 普通正文与背景满足至少 4.5:1 对比度；大文字和图标满足至少 3:1。
- 点击目标原则上不小于 32 px 高；主要危险按钮不小于 34 px 高。
- 不通过 hover 才显示关键操作或文件状态。
- Windows 125% 和 150% 缩放下不得截断按钮文字、格式徽标和删除数量。

## 10. UI 验收测试

### 10.1 视觉快照

在至少以下窗口条件生成并人工检查快照：

- 1440 × 900，100% 缩放
- 1280 × 720，100% 缩放
- 1440 × 900，Windows 150% 缩放
- 长文件名、缺失 EXIF、JPG-only、RAF-only、配对 Photo
- 0、1、12 和大量待删除项目；0 项快照必须是没有待删除页签和底栏计数的图库，而不是待删除空页
- 仅有有效标记、仅有问题项，以及同时存在有效标记与 `NeedsAttention` 的状态
- 冷启动无标记、冷启动恢复标记，以及冷启动恢复问题项

### 10.2 布局验收

- 图库和待删除页的照片画布始终是最大区域。
- 右栏按钮始终位于底部，和参数区之间存在可见留白。
- 参数内容较多时只滚动上方信息区，不把底部按钮推离视口。
- 待删除页不存在 Photoshop 和文件位置按钮或不可用占位。
- 待删除页不存在复选框或“只执行选中项”。
- 图库页不默认显示绝对路径；待删除页只显示相对路径。
- `pendingReviewCount = 0` 时顶栏和底栏都不保留待删除控件、零计数或占位间距。
- 只有问题项时仍能看到“待删除 N”入口和明确的问题数量，但“执行删除…”不会把问题项算入可执行批次。
- 删除问题项的处理按钮仍固定在右栏底部，不能把 Photoshop 或文件位置按钮带入该页。

### 10.3 交互验收

- `←/→/D/R`、Filmstrip 点击和鼠标滚轮使用同一选中状态。
- pending 写入期间不能因重复按键越过照片。
- 无待处理项时启动进入图库，不显示待删除页签或底栏计数；失效的待删除直达路由也回到图库。
- 图库页首次标记成功后徽标、计数和页签同步更新，前进到下一张但不自动切换到待删除视图；命令失败时三者都不得提前变化。
- `R` 恢复标记时能重新显示入口；`R` 或按钮取消使计数归零时能按相同权威摘要隐藏入口。
- 待删除页取消当前项后按已确认规则选择下一项或上一项。
- 在待删除页取消最后一项后回到图库并定位被取消的 Photo，不出现待删除空状态。
- “执行删除…”只打开最终确认，不直接调用文件系统。
- 成功删除最后一项后回到图库的最近下一张，无下一张时回到上一张；部分失败或 `NeedsAttention` 时保留入口和问题项。
- `RetryableFailed`/`Partial` 可在再次确认后只重试身份匹配的剩余文件，也可取消剩余删除；旧结果在报告中保持不变。
- `NeedsAttention` 在重新扫描前不显示重试入口；无法证明结果时不会出现“标记为成功”。
- 快照失效、成员变化、缺失、离线和 hard link 问题均出现第 6.6 节规定的取消/重连/重扫动作；任何路径都不会自动刷新旧标记快照。
- Windows 回收站恢复出的照片经扫描后回到图库且没有旧待删除标记。
- 重启恢复标记或问题项时默认仍进入图库，但首屏显示正确的待删除页签、总数和问题数，不自动进入复核页。
- 对话框关闭后焦点回到发起按钮，取消不会改变标记。
- “设置”可通过键盘打开且不出现在照片页签集合中；从设置返回恢复来源视图与 Photo，焦点返回设置按钮，失效来源路由按保护规则回到图库。
- 活动 Import 时进入待删除页不会开放删除执行；活动 Recycle 时状态栏可返回任务且 `D/R` 保持暂停。活动任务摘要不暴露内部 ID。
